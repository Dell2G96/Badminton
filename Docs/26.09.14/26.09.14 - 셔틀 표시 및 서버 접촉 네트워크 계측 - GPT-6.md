# 셔틀 표시 및 서버 접촉 네트워크 계측

작성일: 2026-09-14 · 모델: GPT-6

## 요청과 선택한 단계

사용자 요청: 다음 작업 진행. 조준 패키지 검증 이후 남아 있던 네트워크 표시·판정의 계측을 진행한다. EQS/EOS 실제 계정 및 외부망 테스트 보류는 유지한다.

## 구현

- 개발 실행에 -BadmintonNetMetrics를 지정하면 계측 로그를 출력한다. Shipping에서는 비활성화되며 새 RPC나 복제 속성은 추가하지 않는다.
- 참가자 셔틀 비행 중 약 10Hz로 상태 나이, 외삽 목표와 표시 위치 사이 거리, 해당 프레임 표시 이동량, 보간 후 잔여 거리, DeltaTime, 엔진 PlayerState Ping, 150ms 외삽 상한 초과 여부를 기록한다.
- 샷 전환 및 정지 상태에서 즉시 위치를 설정한 거리는 별도의 RESET 이벤트로 기록한다. 첫 복제 초기 위치는 제외한다.
- GameMode.TryShot에 도달한 접촉 판정에 진영·랠리·샷·성공 여부·첫 실패 조건·거리·높이를 기록한다. 기존 판정 조건과 검사 순서를 유지하며 묶여 있던 실패 조건을 사유별로 구분한다.
- Scripts/Test-BadmintonNetwork.ps1에 -NetMetrics를 추가했다. 성공한 검사의 호스트·참가자 로그를 Scripts/Measure-BadmintonNetwork.ps1에서 읽어 날짜별 Markdown 통계로 저장한다.
- 보고서의 중앙값은 짝수일 때 가운데 두 값의 평균, p95는 nearest-rank 방식이다. 스크립트 -SelfTest에서 알려진 홀짝 표본·빈 표본·비유한값 제외를 확인했다.

## 지표의 의미

이번 수치는 클라이언트 로컬 표시 모델의 진단값이다. 서버의 같은 순간 실제 위치와 직접 비교한 오차는 아니다. 상태 나이는 동기화된 서버 시간 추정의 영향을 받으며 음수도 숨기지 않는다. 엔진 Ping은 평활된 값으로 별도 RTT 왕복 프로브를 새로 만든 것은 아니다. 0 또는 미확정 Ping은 -1로 기록하고 통계에서 제외한다.

프레임 표시 이동에는 정상적인 셔틀 비행도 포함된다. 샷 전환·서브 재배치 거리도 일반 비행과 분리한다. 전체 입력에 대한 거절률을 주장하지 않으며, 접촉 판정 통계는 GAS를 통과해 TryShot에 도달한 호출만 분모로 삼는다. HUD의 CanActivateAbility 조회를 입력 실패로 집계하지 않는다.

보고서를 게임 종료 후 다시 생성할 때 종료 대기 중 추가 프레임이 섞이는 것을 발견했다. 각 프로세스의 첫 TEST PASS/FAIL까지로 구간을 고정하고 위 표와 원본 보고서를 다시 산출했다. 따라서 위 값은 최초 진행 중 보고서보다 표본 수가 작으며 최종 집계 기준을 따른다.

## 능력 회귀 검증의 실패 기록

첫 계측 활성화 능력 검사(20260914-134654-20703)에서 참가자의 첫 드롭 발동/즉시 단일 비용 검사에 실패했다. 서버 로그에는 해당 참가자의 TryShot 호출이 없으므로 접촉 거리·높이 거절을 원인으로 단정하지 않는다. 이 실패는 보존하며 전체 검사 통과로 표시하지 않는다.

계측을 끈 동일 50ms/1% 조건(20260914-134801-20704)은 양쪽 비용·부족·무료 클리어·오래된/잘못된 조준 입력·연속 입력·대시 이동 검사를 통과했다. 한 번씩의 결과로 계측 인과관계나 해결 완료를 단정하지 않는다. 실패 시 실제 능력 Spec 존재, 준비·태그, 전후 스태미나·기대 비용을 출력하도록 개발 전용 능력 프로브 진단을 보강한 뒤 계측 활성화 비교를 진행한다. 판정과 검사 허용 오차는 변경하지 않았다.

## 실행 및 재분석

프로젝트 루트 `D:/_Projects/FPS_Dell2g`에서 실행한다.

```powershell
# 패키지로 50ms/1% 자동 조준 랠리와 계측 보고서 생성
./Scripts/Test-BadmintonNetwork.ps1 -TestKind Aim -Port 20706 -OneWayLagMs 50 -PacketLossPercent 1 -NetMetrics -GameExecutable 'D:/_Projects/FPS_Dell2g/Saved/Packages/BadmintonMVP/Windows/FPS_Dell2g/Binaries/Win64/FPS_Dell2g.exe'

# 보존된 로그 재분석: 게임을 실행하지 않는다
./Scripts/Measure-BadmintonNetwork.ps1 -HostLog 'Saved/Logs/BadmintonHost-20260914-135242-20706.log' -ClientLog 'Saved/Logs/BadmintonClient-20260914-135242-20706.log' -OneWayLagMs 50 -PacketLossPercent 1 -RequireFlightSamples

# 보고서 통계 계산 검사
./Scripts/Measure-BadmintonNetwork.ps1 -SelfTest
```

자동 검사에서는 -NetMetrics가 게임의 -BadmintonNetMetrics로 전달된다. 수동 개발 실행에서도 게임 인수에 -BadmintonNetMetrics를 지정할 수 있다. 수동 로그에 TEST 완료 마커가 없으면 로그를 읽은 전체 구간을 집계하므로 실행 조건과 기록 시간을 함께 남긴다.

## 남은 작업 및 최종 안내

1. 서버 시간 추정과 Tick 순서를 조사해 음수 상태 나이의 원인을 확인한다. 그 이후에 외삽과 표시 보정 개선을 검토한다.
2. 첫 능력 검사 실패가 재현되면 추가 진단의 Spec·태그·전후 비용을 확인한다. 테스트 허용 오차를 늘려 통과 처리하지 않았다.
3. 실제 마우스 입력 반응·타격 거절률, 별도 PC와 외부망, MP4·PIE는 남아 있다. 이번 엔진 Ping과 로컬 표시 거리를 실제 같은 시점의 서버 위치 오차나 독립 RTT 측정으로 표시하지 않는다.
4. EQS/EOS 테스트 보류를 유지했다. 최종 테스트 프로세스는 검사 도구가 자신이 시작한 것만 정리한다. 커밋·외부 게시·OBS 조작을 수행하지 않았다.

최종 안내: 셔틀 표시와 서버 접촉 판정의 선택적 계측 및 Markdown 보고서 생성을 구현했다. 세 지연·손실 조건의 조준 랠리, 자동화 7건, 최종 패키지 조준·능력·경기·화면 검증을 완료했다. 능력 검사 1회 실패는 후속 재검사에서 재현되지 않았으며 원인 미확정 이력으로 보존했다. 전체 작업 단계별 문서도 갱신했다.
