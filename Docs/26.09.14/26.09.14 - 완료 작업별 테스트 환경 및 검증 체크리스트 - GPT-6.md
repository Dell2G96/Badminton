## 2. 직접 게임을 켜서 확인하는 방법

### 2.1 같은 PC의 패키지 2개 창 — E4

1. 프로젝트 루트의 `Start-BadmintonPackage.cmd`를 실행하고 **2번 Host local IP room**을 선택한다.
2. 런처를 한 번 더 실행하고 **3번 Join local host**를 선택한다.
3. 각 창을 클릭해 입력 포커스를 준 뒤 양쪽에서 Enter를 누른다.
4. 서브권이 표시된 창에서 왼쪽 클릭으로 서브한다.
5. 수신자는 셔틀 아래로 이동해 왼쪽 클릭으로 리턴한다.

1번은 상대를 기다리는 단독 코트이며 AI 상대가 생기는 모드가 아니다. 4번 EOS 모드는 현재 보류 범위다. 같은 PC에서는 키보드·마우스 포커스가 한 창에만 있으므로, 창 전환으로 확인하는 검사와 실제 두 사람이 동시에 플레이하는 검사를 구분한다.

### 2.2 실제 조작키

| 입력 | 동작 | 확인 포인트 |
|---|---|---|
| W / A / S / D | 코트 이동 | 양쪽 진영에서 W가 네트 방향인지 확인 |
| Enter | 준비/준비 취소, 경기 종료 후 재경기 준비 | 두 사람 모두 준비해야 시작. 랠리 중 준비 취소로 상태가 깨지지 않아야 함 |
| 왼쪽 클릭 | 서브 대기에서는 서브, 랠리에서는 클리어 | 현재 경기 단계에 맞게 전환 |
| 오른쪽 클릭 | 드롭 | 짧은 샷, 기본 비용 8 |
| Space | 스매시 | 높은 타점 필요, 기본 비용 18. 점프키로 기대하지 않음 |
| 왼쪽 Shift | 대시 | 이동 입력 방향, 입력이 없으면 네트 방향. 기본 비용 25 |
| 마우스 이동 | 상대 코트 목표 조준 조정 | 마우스 이동량 기반. 화면의 절대 커서 위치를 찍는 방식이 아님 |
| 가운데 클릭 | 조준 초기화 | 조준과 미리보기 샷을 초기 상태로 복귀 |

코드 기본값은 서브/클리어 비용 0, 최대 스태미나 100, 초당 회복 12다. 샷별 실제 기준은 실행 중 참조하는 `DA_BadmintonShots`와 HUD 비용을 함께 확인한다. 에셋을 튜닝한 빌드에 이전 숫자를 무조건 적용하지 않는다.

### 2.3 에디터·LAN 환경

- E2: 에디터에서 대상 맵을 열고 Listen Server / 플레이어 2명으로 PIE를 구성한다. 양쪽 로컬 창의 Pawn·PlayerState·ASC를 구분한다. 인프로세스 PIE는 같은 PC 공통 시각 추적용 두 로그로 취급하지 않는다.
- E3 수동 실행: `Scripts/Start-Badminton.ps1`의 Host와 Join 모드를 사용한다. 자동 프로브를 켠 게임은 자동으로 이동·준비·타격하므로 수동 조작 시험용으로 사용하지 않는다.
- E5: 두 PC에 같은 패키지의 **Windows 폴더 전체**를 복사한다. 호스트는 Host 모드, 참가자는 실제 호스트 LAN IPv4와 포트 7777로 Join한다. 참가자 PC에서 `127.0.0.1`은 호스트 PC가 아니다. 현지 네트워크와 Windows 방화벽에서 해당 게임의 LAN 통신이 허용된 상태로 검사한다.
- 패키지 CMD 런처에는 현재 PC의 PowerShell 7 경로가 들어 있다. 다른 PC에서는 설치된 PowerShell 7로 스크립트를 실행하거나 패키지 exe를 직접 실행한다. CMD 경로 문제를 게임 바이너리 실패로 분류하지 않는다.

## 4. 기반·접속·이동 체크리스트

각 항목은 새 검사에서 확인하면 체크한다. 실패하면 11절 양식에 환경·재현 절차·로그를 남긴다.

### 기반

- [ ] **B01 — 범위 대조 / E0:** 1대1, 1코트, 랠리당 1점, 11점 선취·듀스 없음, 기본 타격 무료임을 확인한다. 2대2·AI·랭크·정식 캐릭터를 완료 기능으로 기대하지 않는다.
- [ ] **B02 — 에디터 로딩 / E0/E2:** 프로젝트와 대상 맵을 열고 배드민턴 GameMode·코트·카메라·캐릭터가 로딩되는지 확인한다. 기본 FPS 맵이 열리거나 참조 누락으로 기본값이 잘못 적용되면 실패다.
- [ ] **B03 — 패키지 로딩 / E4/E5:** Windows 폴더 전체로 호스트와 참가자를 실행한다. 맵/필수 DLL/샷 에셋이 로딩되고 양쪽 빌드 해시가 같아야 한다. exe 하나만 복사해 실행한 오류는 별도 배포 구성 문제로 기록한다.
- [ ] **B04 — 데이터 반영 / E0/E2/E4:** `/Game/Badminton/Data/DA_BadmintonShots`와 GameState 참조를 확인한다. HUD 비용과 실제 비용이 같아야 한다. 자동 `Shots.TrajectoryAndCosts`는 C++ 기본값 검사이므로 튜닝한 에셋 전체 검증의 대체가 아니다.

### 접속·이동·준비

- [ ] **C01 — 2인 배치 / E2~E5:** 호스트→참가자 순서로 입장한다. 서로 다른 코트 진영, 상대 캐릭터, 2/2 인원이 보이고 카메라는 각자의 후방에서 상대를 바라봐야 한다.
- [ ] **C02 — 이동과 경계 / E2~E5:** 양쪽에서 W/S/A/D를 각각 누르고 코트 네 방향 경계까지 이동한다. W는 양쪽 모두 네트 방향이며 자기 이동이 상대에게 전달돼야 한다. 경계 밖이나 상대 진영으로 정상 이동이 뚫리지 않아야 한다. 자동 검사는 C2 명령의 Movement를 사용한다.
- [ ] **C03 — 준비·취소 / E2/E4/E5:** 한 명만 Enter→준비 취소→다시 준비→상대 준비 순으로 실행한다. 한 명만 준비하면 시작하지 않고 두 명 준비 시 서브 대기로 넘어가야 한다. 경기 중 Enter로 점수나 경기 단계가 초기화되면 실패다.
- [ ] **C04 — 정원 / E3/E4/E5:** 호스트+참가자로 2명이 접속한 뒤 세 번째 프로세스로 접속한다. `BadmintonRoomFull`로 거절되고 기존 2인의 경기가 유지돼야 한다. 명령 C5 참조.
- [ ] **C05 — 참가자 이탈·재접속 / E3~E5:** 경기 중 참가자 프로세스를 정상 종료하고 같은 방에 재접속한다. 호스트는 1인 대기로 복귀하고, 재접속 후 2인 준비 대기로 가야 한다. 이전 랠리·준비·능력이 새 경기로 남지 않아야 한다.
- [ ] **C06 — 호스트 종료 / E3~E5:** 참가자가 연결된 상태에서 호스트를 종료한다. 참가자에 연결 종료 안내가 나오고 오프라인 1인 코트로 복귀해야 한다. 무한 연결 대기나 이전 경기 HUD 고정은 실패다.
- [ ] **C07 — 역할 교환 / E5:** PC A를 호스트로 한 검사 뒤 PC B를 호스트로 바꿔 C01~C06과 실제 랠리를 반복한다. 자동 Match는 기본적으로 side 0 승리 흐름이므로 참가자 승리와 네트워크 역할 교환을 따로 확인한다.

통과 증거: 양쪽 화면, 각 프로세스 로그, `BADMINTON_NET_TEST PASS`, 정원/재접속/호스트 종료 PASS 마커. 연결 검사 성공은 EOS 로그인·로비 복구 성공을 뜻하지 않는다.

## 5. GAS·샷·비행·경기 체크리스트

### GAS와 샷

- [ ] **G01 — ASC 초기화 / E1/E2/E3:** 참가자 입장 후 PlayerState의 ASC가 해당 Pawn을 Avatar로 참조하고 능력 Spec이 한 번씩 부여됐는지 확인한다. 초기 스태미나는 100, 능력 중복 부여·이전 Pawn 참조·초기화되지 않은 능력은 없어야 한다. Movement 프로브가 기본 초기화를 함께 검사한다.
- [ ] **G02 — 단일 비용 / E2~E5:** 랠리에서 드롭·스매시·대시를 한 번씩 발동한다. 발동 승인 즉시 해당 비용이 한 번만 차감돼야 한다. 스태미나가 계속 회복하므로 몇 프레임 뒤의 HUD 숫자만으로 정확한 비용을 판정하지 말고 Abilities 프로브의 발동 전후 값을 확인한다.
- [ ] **G03 — 부족·무료 타격 / E1/E2/E3:** Abilities 프로브에서 스태미나 부족 시 유료 능력 차단과 무료 클리어의 비용 조건을 확인한다. 수동으로는 반복 유료 행동으로 스태미나를 낮춘 뒤 확인한다. 클리어가 무료여도 경기 단계·회복 태그·접촉 거리 등의 다른 조건까지 무시하고 성공해야 하는 것은 아니다.
- [ ] **G04 — 헛스윙·연속·잘못된 입력 / E2/E3/E4:** 셔틀과 멀리 떨어져 유료 샷을 시도하고 빠르게 연속 입력한다. 승인된 헛스윙 비용은 유지하지만 접촉 성공은 없어야 한다. 동일 회복 구간의 중복 발동·추가 비용은 차단돼야 한다. 오래된 랠리·잘못된 TargetData는 Abilities/Aim 자동 검사로 검증하며 임의 콘솔 명령이 있다고 가정하지 않는다.
- [ ] **G05 — 샷 차이 / E1/E2/E5:** 동일 진영에서 클리어·드롭·스매시를 가능한 타점에서 비교한다. 드롭은 짧고 스매시는 클리어보다 빠른 기본 궤적이어야 한다. 기본 스매시 최소 타점 220cm 아래에서는 서버 접촉이 실패해야 한다. 비용 발동 성공과 실제 접촉 성공을 구분한다.
- [ ] **G06 — 대시·회복·취소 / E2~E5:** 네 방향 이동 중 Shift, 무입력 상태 Shift, 경계 부근 Shift를 확인한다. 방향과 이동 복제가 맞고 경계를 뚫지 않아야 한다. 회복 후 재발동이 가능해야 하며 득점·경기 종료·이탈 때 진행 중 능력 상태가 남지 않아야 한다.

기본 데이터 참고: 드롭 8, 스매시 18, 대시 25, 회복 초당 12. 대시 기본 속도 950cm/s·지속 0.18초·회복 0.65초다. 튜닝한 에셋에는 그 실행의 실제 데이터를 기준으로 한다.

### 셔틀 비행과 판정

- [ ] **F01 — 수치 궤적 / E1:** Flight 두 검사와 Shots 검사를 실행한다. 30/60/120fps에서 목표 도달 오차 1cm 미만, 하강 타점, 진영 대칭, 각 기본 샷의 의도된 높이에서 네트 통과를 확인한다.
- [ ] **F02 — 연속 랠리 / E3/E4/E5:** 자동 Rally 또는 Aim을 실행한다. **같은 랠리에서 양쪽이 교대로 10회 타격**해야 한다. 여러 랠리에서 합계 10회는 통과가 아니다. 수동 E5에서는 실패한 입력 횟수와 체감 끊김도 함께 기록한다.
- [ ] **F03 — 접촉 권한 / E1/E2/E3:** 너무 멀리·너무 낮게·너무 높게·네트를 아직 넘지 않은 시점·직전 타격자가 다시 치는 상황을 확인한다. 서버가 거리/높이/같은 타격자/유효 통과 조건을 지켜야 한다. `TryShot`까지 도달한 경우 N02의 사유 로그를 대조한다. 자동 능력 검사에 모든 거리 경계 사례가 들어 있다고 가정하지 않는다.

### 서브·득점·종료·재경기

- [ ] **R01 — 서브권·위치 / E1/E2/E5:** 수신자가 먼저 서브를 시도하고, 서브권자가 잘못된 서비스 반쪽 또는 쇼트 서비스 라인 앞에서 시도한 뒤 정상 위치로 돌아온다. 잘못된 서브 접촉은 차단되고 올바른 상태의 서브만 랠리를 시작해야 한다.
- [ ] **R02 — 점수 홀짝·대각 서비스 / E1/E2/E5:** 서브권자의 점수가 짝수/홀수인 상황과 두 진영을 확인한다. 시작 위치와 상대 대각 서비스 목표가 점수에 맞아야 한다. 조준을 끝까지 움직여도 서브 목표가 유효 서비스 구역에 있어야 한다.
- [ ] **R03 — 인/아웃·네트 / E1/E2/E5:** Rules 자동 검사로 경계선 포함 인, 경계 바로 밖 아웃, 짧은 서비스와 잘못된 반쪽, 유효하지 않은 네트 통과를 확인한다. 현재 코드 기준 코트 경계는 `|X|≤670`, `|Y|≤259`cm다. 정상 조준 범위로 만들기 어려운 아웃 사례는 단위 검사를 기준으로 한다. 실제 네트 접촉은 즉시 득점시킬 사건이 아니라 이후 통과·낙하 판정과 함께 확인한다.
- [ ] **R04 — 단일 득점·종료 / E1/E3/E4/E5:** Match 프로브로 랠리당 1점, 중복 득점 호출 무시, 이전 랠리 타격 거절, 11:0 종료와 양쪽 결과 일치를 확인한다. 수동으로는 참가자 승리와 10:10→11:10 종료도 확인한다. 듀스 없는 규칙이므로 2점 차를 기다리면 실패다.
- [ ] **R05 — 재경기·지속 / E3~E5:** 경기 종료 뒤 한 명만 준비할 때 대기하고, 양쪽 준비 시 0:0·스태미나 초기화·새 경기 상태로 시작하는지 확인한다. 10경기 자동 검사는 결과 10회, 재경기 10회, 고유 랠리 득점 110개를 확인한다. Match 프로브는 11:0 흐름이므로 다양한 점수 조합은 E5에서 별도 검사한다.

통과 증거: `BADMINTON_ABILITY_TEST PASS`, `BADMINTON_SHOT_TEST PASS`, `BADMINTON_MATCH_TEST PASS`, `BADMINTON_MATCH_SERIES PASS`, 자동화 결과 JSON, 실제 역할별 영상.

## 6. HUD·연출·마우스 조준 체크리스트

- [ ] **U01 — 단계별 HUD / E2/E4/E5/E7:** 상대 없음→준비 대기→서브 대기→랠리→득점→결과→재경기 순으로 화면을 확인한다. YOU/OPPONENT 점수와 서브·수신 역할은 각자의 관점에서 맞아야 한다.
- [ ] **U02 — 능력 카드 / E2/E4/E5:** READY, WAIT, RECOVERING, LOW STAMINA를 실제 상태와 대조한다. READY는 GAS 발동 가능 표시이며 접촉 성공 보장이 아니다. 카드를 보고만 있어도 비용이 차감되거나 능력이 발동하면 실패다.
- [ ] **U03 — 가독성 / E4/E7:** 960×540, 1280×720, 목표 배포 해상도 1920×1080에서 확인한다. 점수·힌트·2×2 능력 카드·스태미나·성공 안내가 잘리거나 코트를 과도하게 가리지 않아야 한다. 밝은 바닥 위 AIM 글자 배경을 확인한다. 1080p/60fps 성능은 과거 저해상도 캡처 통과로 대체하지 않는다.
- [ ] **U04 — 스윙과 피드백 / E3/E4/E5/E7:** Presentation 프로브로 양쪽 각각 localSwings=5, remoteSwings=5, contacts=5를 확인한다. 수동으로 성공/헛스윙을 번갈아 시도해 CONNECTED/NO CONTACT가 결과와 맞고 한 번씩 표시되는지 확인한다. 패킷이 늦어 연출 지속 시간이 지난 원격 스윙은 생략될 수 있으므로 고지연에서 무조건 같은 횟수를 보장한다고 판단하지 않는다.
- [ ] **U05 — 오래된 표시 정리 / E2/E4/E5:** 득점·새 서브·재경기·이탈 직후 이전 타격 피드백과 셔틀 잔상이 남지 않아야 한다. 셔틀 추적 그림을 착지 예측 또는 별도 타격 판정으로 해석하지 않는다.
- [ ] **A01 — 실제 마우스 / E2/E4/E5:** 양쪽 진영에서 마우스를 좌우/상하로 이동해 AIM 목표가 기대한 방향으로 변하는지 확인한다. 작은 이동·연속 큰 이동·창 포커스 전환을 검사한다. Aim 자동 프로브는 고정 조준값을 쓰므로 이 검사를 대체하지 않는다.
- [ ] **A02 — 초기화·미리보기 / E2/E4/E5:** 조준을 변경한 뒤 가운데 클릭, 득점 후 새 랠리를 각각 확인한다. 조준 초기화와 샷 미리보기 복귀가 맞아야 한다. 드롭/스매시 입력 뒤 미리보기 종류를 확인한다. 현재 입력한 샷 종류를 기억하는 방식이지 별도의 샷 선택 메뉴가 있는 것은 아니다.
- [ ] **A03 — 범위·서버 목표 / E1/E3/E4:** 조준 중앙·끝값, 두 진영, 점수 홀짝을 단위 검사로 확인한다. Aim 프로브에서는 (0.5,0.25) 조준과 서버가 재계산한 목표가 샷 10개 동안 양쪽에 순서대로 전달돼야 한다. NaN/Inf·잘못된 진영·잘못된 페이로드는 자동 검사에서 거절한다.
- [ ] **A04 — 프레임률별 조작 / E2/E4/E5:** 같은 장치·감도로 30/60/120fps 제한을 비교하고 실제 마우스 이동에 따른 조준 변화와 끊김을 기록한다. 코드의 비행 수치 검사와 실제 마우스 감도 검사를 구분한다. 사람의 이동 오차가 있으므로 육안 차이를 정밀 성능 수치로 표시하지 않는다.

E7 자동 캡처는 C7 명령으로 생성하고 이미지를 직접 검토한다. 캡처 파일 생성 PASS만으로 화면 내용·레이아웃 통과를 체크하지 않는다. 최종 캐릭터 애니메이션·사운드·완성형 라켓 그립·한글 UI는 완료 기능 검사의 대상이 아니다.

## 7. 네트워크·계측 체크리스트

- [ ] **N01 — 조건 조합 / E3/E4:** 편도 지연 0/25/50/75ms × 송신 손실 0/1/3%의 12개 조건에서 같은 랠리 10회 교대 타격을 검사한다. 새 실행마다 양쪽 PASS와 서버 랠리 ID·교대 순서를 확인한다. 조건별 비교는 순차 실행하고 다른 게임·빌드를 동시에 돌리지 않는다.
- [ ] **N02 — 기존 계측 / E3/E4:** NetMetrics를 켜고 비행 표본, 엔진 Ping, 원시 상태 나이, 보간 전/후 로컬 목표 거리, 서버 접촉 성공/첫 실패 사유가 출력되는지 확인한다. 자동 Aim/Rally/Presentation 보고서는 비행·접촉 각각 최소 10개 조건을 검사한다. 입력 전체가 아닌 `TryShot` 도달 건수만 접촉 판정 분모다.
- [ ] **N03 — 비활성화·재분석 / E3/E4/E1:** 옵션 없는 실행에서 `BADMINTON_METRIC_`가 없어야 한다. 같은 종료 로그를 두 번 분석한 보고서 해시가 같아야 한다. 첫 TEST PASS/FAIL 이후 종료 대기 프레임이 재분석 때 추가돼서는 안 된다. 수동 로그에 완료 마커가 없으면 전체 읽기 구간을 쓴다는 차이를 기록한다.
- [ ] **N04 — 수신 시간 하한 / E1/E3/E4:** 원시 나이가 음수인 경우 `receipt_ms`와 `present_ms`를 확인한다. 수신 뒤 게임 시간이 흘렀으면 그 하한으로 외삽이 진행하고 실제 적용 외삽은 150ms 이하여야 한다. 원시 음수가 없어야 한다는 기준을 세우지 않는다. 긴 미수신·정지·새 스냅샷·시각 원점 이동은 Presentation 자동화 3개로 확인한다.
- [ ] **N05 — 공통 시각 위치 비교 / 같은 PC E3/E4:** PositionTrace를 켜고 동일 GUID·머신·Windows QPC로 수집됐는지 확인한다. 유효 비교 30개 이상, 위치 차이·과거 궤적 시차·잔여 거리·서버 보간 구간과 제외 표본 수가 보고서에 있어야 한다. 50ms 초과 구간과 전환·충돌·샷 불일치를 정상 비행에 섞지 않아야 한다.
- [ ] **N06 — 분석 경계 / E1:** 위치 분석 SelfTest에서 알려진 100ms 시차와 3cm 횡오차, 동시 좌표, 300ms 탐색 상한, 정지·시간 범위·충돌 경계 제외를 확인한다. SameMachine 누락·다른 실행 GUID·다른 머신의 로그 결합은 거절해야 한다. 같은 로그 재분석 결과는 동일해야 한다.
- [ ] **N07 — 시계 선택·계측 / E3/E4:** C11로 같은 빌드의 Legacy와 RoundTrip을 순차 실행한다. 추적 보고서 모델 이름이 선택과 같고, Legacy의 CLOCK_SAMPLE은 0건이어야 한다. RoundTrip의 유효 응답 뒤 clock_synced=1, 선택 RTT가 기록돼야 한다. NetMetrics만으로 후보 RPC가 켜지면 실패다. 옵션 없는 일반 실행과 Shipping은 기존 방식이다.
- [ ] **N08 — 만료·재접속 / E1/E3/E4:** Clock.ExpiryPauseAndWorldTimeReset으로 3초 응답 만료·로컬 정지·시간 초기화 시 기존 방식으로 돌아가는 조건을 검사한다. RoundTrip을 선택한 Movement+CheckReconnect+CheckHostLoss로 새 컨트롤러 접속과 오프라인 복구도 확인한다. 실제 장기 미수신·서버만 정지하는 운영 조건은 별도 수동 검증이 필요하다.
- [ ] **N09 — 응답 검증·보정 한도 / E1:** Clock의 순서/중복/비유한 응답 거절, 1초 초과 RTT 무효화, 최근 8초/최대 8표본의 최소 RTT 선택, 기존 offset의 응답당 5ms 보정 상한을 검사한다. 최초·만료 후 새 기준 설정과 이후 완만한 보정을 구분한다.
- [ ] **N10 — 후보 채택 전 반복 랠리 / E3/E4/E5:** 0ms/0%, 50ms/1%, 75ms/3%에서 두 모델의 실행 횟수·성공·실패·제외 표본을 모두 남긴다. 낮은 위치 오차만으로 채택하지 않고 같은 랠리 10회 교대와 서버 접촉 결과도 확인한다. 19단계 후보는 75ms/3%에서 두 차례 실패해 기본 적용을 보류했다. 스트레스 실패의 원인·반복 안정성을 해결하기 전 완료 체크하지 않는다.
- [ ] **N11 — 타격 흐름 연결 / E3/E4:** C12의 ShotFlow로 Input→Activate→Contact→End 로그와 보고서를 확인한다. 플레이어·샷·예측 키를 연결하고 소프트웨어 입력→로컬 활성화·로컬→서버 활성화·서버 내부 접촉 시간을 구분한다. 서버 활성화 미관측은 엔진의 사전 거절 로그를 추가 확인한다.
- [ ] **N12 — 실패 진단·보존 / E3/E4:** 중간에 랠리가 끝나면 Aim FAIL에 점수·관측 샷 수와 `rally ended before ten alternating shots`가 나오는지 확인한다. 실패 종료 코드와 원본 로그를 보존하며, ShotFlow는 실패 실행에서도 보고서를 생성해야 한다. 메타데이터가 없는 초기화 실패의 분석 경고는 원래 게임 오류를 가리지 않아야 한다.
- [ ] **N13 — 흐름 분석 경계 / E1:** Measure-BadmintonShotFlow SelfTest의 알려진 시간·서버 미관측·키 중복·시각 역전·접촉 거절을 확인한다. SameMachine 누락 및 다른 GUID/모델/머신 로그 결합을 거절해야 한다. 재분석 결과는 같아야 한다. 재접속/장시간 키 재사용 로그를 단일 연결 자료로 넣지 않는다.
- [ ] **N14 — 진단 옵션 독립 / E3/E4:** 일반 실행에서 SHOT_FLOW가 0건인지 확인하고 NetMetrics로만 활성화되는지 비교한다. TransportTrace는 RPC·재전송 조사 때만 추가한다. 통신 로그를 켠 실행의 FPS/시간값을 일반 실행의 성능 보장으로 쓰지 않는다.

### 조건과 수치 해석

| 편도 지연 설정 | 명목 RTT | 손실 조합 | 용도 |
|---:|---:|---|---|
| 0ms | 0ms | 0/1/3% | 기본 및 손실 단독 영향 |
| 25ms | 50ms | 0/1/3% | 낮은 지연 |
| 50ms | 100ms | 0/1/3% | 초기 목표의 대표 조건: 반복 랠리·결과 일치·중복 득점 없음 |
| 75ms | 150ms | 0/1/3% | 스트레스 조건 |

명목 RTT는 설정값의 두 배다. 엔진 Ping은 평활된 관측값이며 명목 RTT와 같아야 한다는 합격 기준이 아니다. RTT 100ms·손실 1% 목표를 말할 때 편도 설정 50ms와 실제 관측 Ping을 함께 기록한다.

**위치 오차나 시차에 대한 확정 제품 합격선은 아직 없다.** 아래 숫자는 이전 실행을 재현·비교하기 위한 참고이며, 넘으면 자동 실패로 처리할 임계값이 아니다.

| 18단계 에디터 기준 실행 | 동시 서버 기준 위치 차이 중앙값/p95(cm) | 과거 궤적 최근접 시차 중앙값/p95(ms) |
|---|---|---|
| 0ms / 0% | 13.457 / 18.903 | 22.101 / 23.325 |
| 50ms / 1% | 48.466 / 68.537 | 76.443 / 85.120 |
| 75ms / 3% | 65.973 / 94.074 | 104.423 / 105.134 |

- 기존 `gap_cm`/`residual_cm`는 로컬 외삽 목표와 표시 사이 거리다. 같은 시점 서버 위치와의 오차가 아니다.
- PositionTrace의 서버 기준도 프레임 표본 사이의 선형 보간 근사이며, 실제 GPU 출력이나 디스플레이 시점을 측정하지 않는다.
- 과거 궤적 시차는 가장 가까운 과거 위치를 찾은 기하학적 추정이다. 네트워크 RTT·편도 전송시간·입력 지연으로 부르지 않는다.
- 샷 전환 불일치로 제외된 표본에도 사용자가 보는 지연이 있을 수 있다. 유효 표본만 제시하지 말고 제외 개수도 기록한다.
- 프레임별 추적 로그 자체의 비용이 있으므로 추적을 켠 수치로 기본 실행의 FPS를 보장하지 않는다.

### C9. 분석기 자체 검사와 기존 로그 재분석

```powershell

# 현재 존재하는 18단계 최종 패키지 로그를 이용한 예시
```

## 9. EOS와 녹화 — 별도 미완료 항목

### EOS: 재개 후에만 실행

- [ ] **O01 / E0/E6:** 로컬 암호화 설정, 제품·Sandbox·Deployment·클라이언트/EAS 연결 관계와 남은 브랜드 조건을 확인한다. 비밀 값이나 토큰을 결과 문서·스크린샷·공개 로그에 복사하지 않는다.
- [ ] **O02 / E6:** 사용자 Windows 환경에서 `Start-BadmintonEOS.cmd` 또는 패키지의 EOS 런처로 실행하고 F1 로그인한다. 서로 다른 두 계정 모두 실제 로그인 성공이어야 한다. 기존 `EOS_Auth_WrongClient`는 해결 완료가 아니다.
- [ ] **O03 / E6:** 호스트 F2 방 생성, 참가자 F3 검색·F4 첫 방 참가를 수행한다. 올바른 호환 방만 보이고 실제 코트에 2명이 연결돼야 한다. 포털 구성됨 표시나 방 목록만으로 완료 처리하지 않는다.
- [ ] **O04 / E6:** 로그인 취소, 로그인 전 생성 요청, 연속 생성/검색/참가 요청을 시도한다. 오류 안내가 복구 가능하고 비동기 요청이 중복되어 상태가 꼬이지 않아야 한다. F1~F5가 뷰 모드 등 다른 기본 디버그 동작을 실행하지 않는지도 확인한다.
- [ ] **O05 / E6:** 별도 외부망에서 랠리·종료·재경기, F5 나가기, 참가자 이탈·호스트 종료 후 재접속을 확인한다. PC·계정·호스트 역할도 바꾼다. 같은 LAN/IP 검사 결과를 이 항목에 사용하지 않는다.

EAS 브랜드/도메인 설정과 실제 인증·외부망은 여전히 배포 완료 조건의 미완료 부분이다. 이 문서 작성에서는 EOS 로그인이나 포털 설정을 실행·변경하지 않았다.
