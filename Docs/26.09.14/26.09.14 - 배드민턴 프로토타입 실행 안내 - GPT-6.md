# 배드민턴 프로토타입 실행 안내

작성일: 2026-09-14 · 작업 모델: GPT-6

## 현재 플레이 가능한 범위

UE 5.7.4에서 두 플레이어의 접속·코트 이동·준비 상태와 GAS 기본 타격, 서버 셔틀콕 비행을 확인하는 연습용 프로토타입이다. 캐릭터·셔틀콕은 임시 도형이며 기본 샷은 상대 코트 중앙을 향한다. 점수·정식 서브 규칙, 드롭·스매시·대시, 애니메이션과 EOS 방 UI는 후속 구현 대상이다.

에디터 시작 맵과 게임 기본 맵은 `/Game/Badminton/Maps/L_Badminton_Prototype`으로 설정했다. 기존 FPS 맵과 배드민턴 시연 맵은 보존했다.

## 실행

PowerShell에서 프로젝트 폴더로 이동한 뒤 실행한다.

```powershell
Set-Location 'D:\_Projects\FPS_Dell2g'

# 에디터에서 프로토타입 맵 열기
.\Scripts\Start-Badminton.ps1 -Mode Editor

# 호스트 게임 창 실행
.\Scripts\Start-Badminton.ps1 -Mode Host

# 같은 PC에서 두 번째 게임 창으로 참가
.\Scripts\Start-Badminton.ps1 -Mode Join -Address '127.0.0.1:7777'
```

다른 PC에서 같은 LAN으로 참가할 때는 `127.0.0.1` 대신 호스트의 LAN IP 주소를 사용한다. 이 경로는 현재 로컬 네트워크 검증용이며 EOS 인터넷 방 접속을 대신하지 않는다.

## 조작과 연습 흐름

1. 호스트와 참가자 창에서 각각 Enter를 눌러 준비한다.
2. WASD로 움직인다. 양쪽 모두 W는 네트 방향이며 각자 코트의 경계를 넘지 못한다.
3. Side 1 플레이어가 자신의 최초 위치 부근에서 좌클릭하여 서브한다.
4. 상대는 셔틀콕이 가까워졌을 때 좌클릭하여 리턴한다. 현재 기본 타격 거리는 180cm이며 타점 높이와 코트 편을 서버에서 검사한다.
5. 셔틀콕이 떨어지면 연습 랠리를 종료하고 1초 뒤 다음 서브를 준비한다. 현재는 점수를 부여하지 않는다.

콘솔에서도 `BadmintonHost`, `BadmintonJoin 127.0.0.1:7777`, `BadmintonReady`, `BadmintonClear`를 사용할 수 있다. 동일 PC의 두 창은 동시에 키보드 입력을 받지 않으므로, 실제 두 사람 조작감 검증은 별도 PC가 적합하다.

## 빌드

```powershell
& 'D:\Game\UE_5.7\Engine\Build\BatchFiles\Build.bat' `
  FPS_Dell2gEditor Win64 Development `
  'D:\_Projects\FPS_Dell2g\FPS_Dell2g.uproject' `
  -WaitMutex -NoHotReloadFromIDE -NoUBA `
  -Log='D:\_Projects\FPS_Dell2g\Saved\Logs\BadmintonBuild.log'
```

현재 환경의 전역 UBA·로그 폴더 접근 문제를 피하도록 빌드 로그를 프로젝트에 저장하고 UBA를 사용하지 않는 예다. 사용자가 승인한 대로 OBSRecording은 임시 비활성화했다.

## 자동 네트워크 검증

```powershell
# 2인 코트 배치·이동 복제·준비 상태·ASC 연결
.\Scripts\Test-BadmintonNetwork.ps1 -TestKind Movement

# 한 랠리에서 양쪽 10회 교대 타격
.\Scripts\Test-BadmintonNetwork.ps1 -TestKind Rally

# 양쪽 송신에 편도 50ms 및 패킷 손실 1% 적용
.\Scripts\Test-BadmintonNetwork.ps1 -TestKind Rally `
  -OneWayLagMs 50 -PacketLossPercent 1 -Port 17778

# 정원 초과 참가도 검사
.\Scripts\Test-BadmintonNetwork.ps1 -TestKind Movement -CheckCapacity
```

테스트는 별도 호스트·클라이언트 프로세스를 숨겨 실행하고 자동 입력으로 검사한 뒤 자신이 시작한 프로세스만 종료한다. `-nullrhi` 테스트는 네트워크·게임 로직 검증이며 화면 품질이나 사람이 느끼는 타격감을 검증하지 않는다. 로그는 엔진 산출물인 `Saved/Logs/Badminton*.log`에 남고 결과 요약은 날짜별 Markdown 작업 기록에 저장한다.

지연 50ms를 양쪽 송신에 설정한 것은 추가 왕복 지연 약 100ms 조건이다. 실제 관측 RTT와 위치 보정 오차의 통계 측정은 후속 단계에서 추가한다.

## 에셋과 버전 관리

현재 저장소의 `.gitignore`는 `Content`, `Docs`, `*.md`를 제외한다. 새 맵과 문서는 로컬에 존재하지만 기본 Git 변경 목록에는 표시되지 않는다. 기존 정책은 변경하지 않았다. 다른 PC에 옮길 때는 소스뿐 아니라 필요한 Content와 새 맵을 포함해야 한다.

새 맵이 없는 사본에서는 `Scripts/create_badminton_map.py`를 UE Python commandlet으로 실행하여 생성할 수 있다. 이 스크립트는 기존 맵을 덮어쓰지 않는다. 코트 머티리얼은 기존 `Content/Badminton/Prototype/` 에셋을 사용하며, 에셋이 없으면 기본 머티리얼로 표시될 수 있다.
