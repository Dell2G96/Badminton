## 해석 범위

- 비행 표본은 비행 중 약 10Hz로 기록한 프레임이다. p95는 정렬 후 ceil(0.95×N)번째 값, 짝수 표본의 중앙값은 가운데 두 값의 평균이다.
- 자동 검사 로그는 각 프로세스의 첫 TEST PASS/FAIL까지로 계측 구간을 고정한다. 종료 후 같은 로그를 다시 분석해도 종료 대기 중 추가 프레임이 통계에 섞이지 않는다. 완료 마커가 없는 수동 실행 로그는 읽은 전체 구간이다.
- 목표는 마지막 서버 상태를 최대 150ms 외삽한 로컬 계산값이다. 신규 형식은 max(서버 추정 시각−상태 시각, 수신 후 로컬 게임 경과 시간, 0)을 상한 내에서 사용한다. 이전 형식은 서버 추정 시각만 사용했다. 거리 수치는 같은 순간의 실제 서버 좌표와 직접 비교한 오차가 아니다.
- 표시 이동량에는 정상적인 셔틀 이동도 포함된다. 네트워크 때문에 발생한 추가 보정량만 분리한 수치는 아니다.
- 상태 나이는 서버 시간 추정값에서 상태 타임스탬프를 뺀 값이다. 시계 보정의 영향을 받으며 실제 편도 지연과 다르다. 음수도 숨기지 않는다.
- 수신 시간 하한은 받은 이후의 시간만 보장한다. 전송 지연을 추정하거나 서버 시계를 동기화하지 않는다. 신규 capped는 두 시간의 최댓값이 150ms를 넘는지 표시한다.
- 엔진 Ping은 PlayerState.GetPingInMilliseconds의 평활된 값이다. 0 또는 미확정은 -1로 기록하고 통계에서 제외한다. 실시간 독립 RTT 프로브가 아니다.
- 샷 전환/정지 위치 설정은 일반 비행 표본과 분리했다. 첫 상태 초기 배치는 제외했고 서브 재배치 거리에는 의도한 게임 전환도 포함된다.
- 접촉 판정 분모는 서버 GameMode.TryShot에 도달한 호출이다. GAS 발동 전 차단·스태미나 부족·잘못된 TargetData 등과 전체 마우스 입력 횟수는 포함하지 않는다. 실패 조건이 여러 개면 코드 검사 순서상 첫 조건만 기록한다.
- 계측은 -BadmintonNetMetrics를 준 개발 실행에서만 활성화되며 추가 RPC·복제 속성·판정 보정을 적용하지 않는다. EOS 인증 정보와 원본 로그 전체는 보고서에 복사하지 않는다.
