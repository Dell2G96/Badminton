# EOS Sandbox 화면 확인 및 후속 설정 안내

작성일: 2026-09-14 · 작업 모델: GPT-6

## 요청과 확인 결과

사용자는 Edge에서 EOS 설정을 직접 진행해 달라고 요청했으며, URL 검증 실패로 자동 조작이 중단된 뒤 현재 화면을 제공했다. 이번 작업은 제공된 화면과 공식 문서를 바탕으로 다음 동작을 안내한다. 포털 설정 변경은 수행하지 않았다.

- 조직 KOREA와 제품 Lee가 존재한다.
- 제품 설정의 샌드박스 탭에 Live, Stage, Dev가 표시된다.
- Live의 디플로이와 ID 제공자 버튼은 활성화되어 있다.
- Stage와 Dev는 비활성화되어 있으며, 화면에 필요한 기능을 사용하기 전까지 기본적으로 비활성화된다는 설명이 있다.
- Deployment 목록, Client와 권한 정책, 실제 EOS 접속은 아직 확인하지 않았다.

## 안내 및 최종 답변

현재 화면은 정상이다. EOS만 사용하는 현재 구성에서는 활성화된 Live Sandbox로 진행하면 된다. Stage와 Dev를 활성화할 필요는 없다. Live라는 이름 자체가 게임의 스토어 출시를 의미하지 않는다.

지금은 화면 중간 **Live 아래의 디플로이 버튼**을 클릭하고, 열린 목록 화면을 캡처해 전달한다. 기존 Deployment를 확인한 뒤 필요한 설정을 이어간다.

근거: [Epic UE 5.7 OSS EOS 공식 문서](https://dev.epicgames.com/documentation/unreal-engine/online-subsystem-eos-plugin-in-unreal-engine?application_version=5.7)는 스토어에 게시하지 않는 제품은 하나의 Sandbox를 사용한다고 설명한다. 현재 Live 사용 판단은 이 설명과 사용자 화면을 함께 근거로 한다.

## 변경 파일과 검증

- AGENTS.md의 제품 미생성 상태를 사용자 화면에서 확인한 상태로 갱신했다.
- 기존 EOS 제품 생성 및 연결 준비 안내에 Live Sandbox 사용 경로를 반영했다.
- 이 문서에 화면 확인 결과, 미확인 범위와 다음 동작을 기록했다.
- 문서 변경 작업이며 코드 빌드와 단계별 게임 테스트는 수행하지 않았다. 테스트 시연 녹화 대상 작업은 아니다.

## 후속 확인: Live Deployment

사용자가 추가로 제공한 Live 샌드박스 디플로이 화면에서 디플로이 1개를 확인했다. 이름은 `Live Deployment`, 유형은 `공개`, 상태는 `활성`, 연동된 아티팩트는 0이다. 이는 포털에 Deployment가 존재한다는 확인이며 게임 연결 성공을 뜻하지 않는다. ID는 화면에 표시되지만 현재 단계에서는 문서에 전사하지 않는다.

다음 안내: 기존 Deployment를 그대로 두고 하단 `닫기`를 누른 뒤 제품 설정 상단의 `클라이언트` 탭을 연다. 클라이언트 목록 화면을 전달받아 기존 항목과 정책을 확인한 다음 구체적인 생성 또는 설정 단계를 안내한다. Client Secret이 보이면 가린 뒤 전달한다.

근거: [Epic의 EOS 제품 설정 안내](https://dev.epicgames.com/documentation/unreal-engine/using-lyra-with-epic-online-services-in-unreal-engine)는 Product Settings의 Clients 탭에서 Client와 Client Policy를 구성하도록 안내한다. 이 문서의 Lyra 전용 추가 요구사항을 본 프로젝트의 필수 조건으로 간주하지 않는다.

이번 후속 작업에서는 포털 변경이나 자격 증명 생성, 게임 테스트를 수행하지 않았다. 확인 결과와 최종 안내를 이 문서에 추가했다.

## 후속 확인: 클라이언트와 정책 미생성

사용자 제공 클라이언트 탭 화면에서 클라이언트 0개와 클라이언트 정책 0개를 확인했다. `새 클라이언트 추가`와 `새 클라이언트 정책 추가` 버튼이 표시된다. 상단에는 Anti-Cheat Services, Epic Account Services, UE Trademarks, Epic Games Store Web Shops Agreement 관련 라이선스 안내가 있다. 이 안내만으로 모든 계약에 동의해야 한다고 판단하지 않는다.

다음 안내 및 최종 답변:

1. 화면 아래쪽 **클라이언트 정책 → 새 클라이언트 정책 추가**를 누른다.
2. 생성 창에서 정책 이름과 유형 입력란이 표시되면 이름은 `BadmintonPeer2Peer`, 유형은 `Peer2Peer`로 선택한다. 이는 플레이어가 호스트가 되는 현재 설계에 사용할 제안값이다.
3. 저장 전 생성 창 화면을 전달받아 실제 권한과 추가 옵션을 확인한다. 아직 생성 창을 확인하지 않았으므로 옵션이 동일하다고 단정하지 않는다.

정책 유형 근거는 앞서 확인한 Epic 공식 Lyra EOS 설정 안내의 Peer2Peer 정책 예시다. 정책의 실제 허용 범위는 생성 창에서 별도로 확인한다. Epic 계정 로그인 설정 시 Epic Account Services 계약 확인이 필요할 수 있으며, 계약 내용은 사용자가 읽고 동의 여부를 결정한다.

현재 포털 변경·정책 생성·자격 증명 생성은 수행하지 않았다. 이번 작업은 화면 확인과 문서 기록이며 게임 빌드·테스트·녹화는 수행하지 않았다.

## 후속 확인: Peer2Peer 정책 생성 창

사용자 제공 화면에서 정책 유형 `Peer2Peer`, 체크된 `User required`, 읽기 전용 정책의 권한 수정이 허용되지 않는다는 안내를 확인했다. 표시된 Lobbies와 Sessions에는 활성화된 작업이 있다. 정책 이름 입력란과 화면 아래의 전체 권한은 현재 캡처에 보이지 않는다. 생성 완료 여부는 아직 확인되지 않았다.

최종 안내:

1. 생성 창 내부를 위로 스크롤하여 정책 이름이 `BadmintonPeer2Peer`인지 확인한다.
2. 유형 `Peer2Peer`와 `User required` 체크를 유지한다. 개별 기능 스위치는 변경하지 않는다. Epic 공식 EOS 설정 예시에서도 플레이어 호스트 구성에 Peer2Peer 정책을 사용한다.
3. 오른쪽 아래 `새 클라이언트 정책 추가`를 눌러 저장한다.
4. 목록에 정책이 생기면 위쪽 `새 클라이언트 추가`를 누르고 열린 생성 창을 전달한다. Client Secret이 표시되면 가린다.

근거: [Epic 공식 EOS 제품 설정 예시](https://dev.epicgames.com/documentation/unreal-engine/using-lyra-with-epic-online-services-in-unreal-engine). 사용자 화면에서 확인한 기본 정책을 유지하는 안내이며, 모든 권한을 개별 검증하거나 실제 네트워크 접속을 검증한 것은 아니다. 이번 작업은 화면 해석 및 안내 기록만 수행했고 포털 조작이나 게임 테스트는 수행하지 않았다.

## 후속 확인: 정책 생성 완료와 클라이언트 추가 준비

사용자의 후속 화면에서 정책 1개가 표시되며 이름은 `BadmintonPeer2Peer`, 유형은 `Peer2Peer`임을 확인했다. 클라이언트는 여전히 0개다. 정책 생성은 사용자 화면을 통해 확인했으며 에이전트가 직접 생성한 것은 아니다.

최종 안내: 위쪽 클라이언트 영역의 `새 클라이언트 추가`를 누른다. 생성 창에 해당 입력란이 표시되면 클라이언트 이름은 `BadmintonGameClient`, 연결 정책은 기존 `BadmintonPeer2Peer`를 선택한다. 나머지 옵션은 실제 생성 창을 확인한 뒤 안내하므로 저장 전 화면을 전달한다. Client Secret이 표시되면 가린다.

이번 작업에서는 화면 확인과 문서 기록만 수행했다. 클라이언트 생성, EOS 연결, 게임 테스트와 녹화는 아직 수행하지 않았다.

## 후속 확인: 클라이언트 생성 창 입력값

사용자 화면에서 클라이언트 이름 `BadmintonGameClient`, 정책 `BadmintonPeer2Peer`가 입력되어 있음을 확인했다. IP 허용 목록과 리디렉션 URL은 비어 있다. 화면 설명상 IP 허용 목록은 지정 CIDR의 출발지로 자격 증명 사용을 제한하며 신뢰할 수 있는 서버에서 사용하는 경우를 위한 옵션이다.

최종 안내: 현재 플레이어 PC에서 실행하는 Windows 게임 클라이언트 생성 단계에서는 IP 허용 목록과 리디렉션 URL을 비워 둔다. 임의의 IP나 포털 주소를 넣지 않는다. 이름과 정책은 현재 값을 유지하고 오른쪽 아래 `새 클라이언트 추가`를 눌러 생성한다. 생성 후 목록 화면에서 결과를 확인하며 Client Secret이 표시되면 가린 뒤 전달한다. 다음 단계는 Epic 계정 로그인에 필요한 Epic Account Services 연결이다.

리디렉션 URL은 자체 웹 OAuth 콜백이나 별도 플랫폼 로그인 흐름을 구성할 때 다시 검토한다. 현재 계획은 UE OSS EOS의 Account Portal 로그인이다. [Epic의 EOS 샘플 설정 자료](https://www.docswell.com/s/EpicGamesJapan/59GNLK-EOS_HowToUseSample_2020)에서도 리디렉션을 사용하지 않는 샘플에서는 해당 URL을 비우도록 안내한다. 이 자료는 과거 샘플 자료이며 현재 모든 인증 방식에 일반화하지 않는다.

이번 작업은 안내와 문서 기록만 수행했으며 클라이언트 생성 완료나 로그인 성공은 아직 확인하지 않았다.

## 후속 확인: BadmintonGameClient 생성 완료

사용자 제공 화면에서 `클라이언트 생성됨`과 `BadmintonGameClient`를 확인했다. Client ID가 표시되고 Client Secret은 마스킹되어 있다. 화면에는 시크릿을 복사하여 안전하게 보관해야 하며 다시 볼 수 없다는 안내가 있다. 비밀 값은 읽거나 기록하지 않았다.

최종 안내:

1. 이 화면을 닫기 전에 클라이언트 비밀 오른쪽의 복사 버튼으로 값을 복사하고, 사용하는 비밀번호 관리자의 보안 메모 등에 클라이언트 ID와 함께 보관한다. 채팅, Docs, Git에는 붙여 넣지 않는다.
2. 보관 후 `클라이언트로 이동`을 누른다.
3. 왼쪽 `에픽 온라인 서비스`를 눌러 열린 화면을 전달한다. 다음 목표는 Epic Account Services의 로그인 애플리케이션과 생성한 클라이언트를 연결하는 것이다. 현재 화면에서는 해당 메뉴 내부 구성을 확인할 수 없으므로 다음 화면을 보고 안내한다.

정책과 클라이언트 생성은 확인되었지만 Epic Account Services 연결, UE 설정, 두 계정 로그인 및 인터넷 방 생성·참가 테스트는 아직 미완료다. 이번 작업은 화면 확인과 문서 기록만 수행했다.

## 후속 확인: EOS 서비스 목록

사용자 화면에서 에픽 온라인 서비스 개요와 계정 및 소셜 영역을 확인했다. 해당 영역에 `에픽 계정 서비스` 카드가 있고 왼쪽 메뉴에도 같은 이름의 항목이 있다. 비밀 키의 로컬 보관 완료 여부는 이 화면만으로 확인할 수 없다.

최종 안내: 상단 `계정 및 소셜` 아래 첫 번째 `에픽 계정 서비스` 카드를 누른다. 왼쪽 메뉴의 같은 항목으로도 이동할 수 있다. 열린 화면을 전달받아 애플리케이션과 클라이언트 연결 절차를 이어간다. 계약 동의 화면이 나오면 사용자가 내용을 읽고 동의 여부를 결정한다.

이번 작업에서는 제공된 화면 확인과 안내 기록만 수행했으며, 계정 서비스 설정 변경이나 약관 동의는 수행하지 않았다.

## 후속 확인: Epic Account Services 애플리케이션 미생성

사용자 제공 화면에서 에픽 계정 서비스의 `애플리케이션(0)`과 `애플리케이션 생성하기` 버튼을 확인했다. 현재 화면에 계약 동의 창은 없으며 계약 동의 완료 여부를 별도로 추정하지 않는다.

최종 안내: 오른쪽 파란색 `+ 애플리케이션 생성하기` 버튼을 누르고 열린 설정 화면을 전달한다. 이름 입력란이 나오면 개발용 이름으로 `Badminton`을 제안한다. 생성 후에는 권한과 연동된 클라이언트 설정을 확인하고 기존 `BadmintonGameClient`를 연결할 예정이다. 실제 생성 화면의 필드와 필수 조건은 아직 확인하지 않았다.

이번 작업은 화면 확인과 안내 기록만 수행했다. 애플리케이션 생성 완료, 클라이언트 연결 및 로그인 성공은 아직 미확인이다.

## 후속 확인: Badminton 브랜드 설정 초안

사용자가 현재 설정이 맞는지 질문했다. 화면에서 애플리케이션 이름 `Badminton`, 초안 모드, 브랜드 설정·권한·연동된 클라이언트가 모두 `구성되지 않음`인 상태를 확인했다. 확인된 도메인이 없다는 안내와 `초안 저장`, `리뷰를 위해 제출` 버튼이 보인다. 현재 화면만으로 초안 저장 가능 여부나 저장 성공을 단정하지 않는다.

최종 답변: 이름은 맞지만 전체 설정은 아직 완료되지 않았다. 개발 테스트 단계에서는 브랜드 심사를 완료할 필요가 없으므로 현재 도메인 경고를 해결하려고 임의의 웹사이트나 개인정보처리방침 URL을 입력하지 않는다. `초안 저장`이 활성화되어 있으면 저장하고, 비활성화되거나 URL을 요구하면 브랜드 설정을 보류한 채 상단 `권한` 탭을 연다. 열린 권한 화면을 전달받아 필요한 권한을 확인하고 다음으로 `BadmintonGameClient`를 연결한다. 현재는 `리뷰를 위해 제출`을 진행하지 않는다.

근거: [Epic 공식 Lyra EOS 설정 안내](https://dev.epicgames.com/documentation/unreal-engine/using-lyra-with-epic-online-services-in-unreal-engine)는 브랜드 설정이 출시 전에는 필요하지만 개발 및 테스트에는 필수가 아니라고 설명한다. 브랜드 검토 전 테스트 계정의 접근 범위는 별도로 확인해야 하며, 공개 사용자 로그인까지 준비된 상태로 간주하지 않는다.

이번 작업은 화면 확인·공식 문서 확인·안내 기록만 수행했다. 초안 저장, 권한 변경, 클라이언트 연결 및 로그인 테스트는 수행하지 않았다.

## 후속 확인: 애플리케이션 권한

사용자 제공 권한 탭에서 Basic Profile은 항상 필수로 활성화되어 있고 Online Presence, Friends, Country는 비활성화되어 있음을 확인했다. `변경 사항 저장` 버튼이 표시된다. 왼쪽 `허용` 버튼은 로그인 동의 화면의 미리보기이며 설정 저장 버튼이 아니다.

현재 구현 목표인 기본 로그인과 게임 내 방 검색·참가는 친구 목록 조회나 온라인 상태 표시를 사용하지 않는 흐름으로 구성할 계획이다. 이에 따라 Basic Profile만 유지하고 나머지 세 권한은 비활성화한 채 `변경 사항 저장`을 누르도록 안내한다. 이후 상단 `연동된 클라이언트` 탭을 열고 BadmintonGameClient 선택 항목이 있으면 선택한 뒤 해당 화면을 전달한다.

UE 연동 시 반드시 포털 권한과 로그인 요청 범위를 맞춘다. 설치된 UE 5.7의 UserManagerEOS.cpp에서 GetAuthScopeFlags()가 EOS 설정의 AuthScopeFlags를 읽고 EOS 로그인 옵션에 적용하는 것을 확인했다. 이후 구성에서는 BasicProfile만 요청하도록 명시하고 친구 조회·Presence 기반 참가·소셜 오버레이 기능을 사용하지 않는 흐름으로 검증한다. 포털에 없는 권한을 엔진 기본값으로 요청하지 않도록 확인한다. 아직 이 엔진 설정을 프로젝트에 적용한 것은 아니다. 친구 초대나 온라인 상태 기능을 실제 도입할 때 관련 포털 권한과 요청 범위를 함께 확장한다.

근거: [Epic UEOSSettings API](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/OnlineSubsystemEOS/UEOSSettings?lang=en-US)의 AuthScopeFlags 정의와 [Epic 친구 및 상태 기능 안내](https://onlineservices.epicgames.com/news/querying-for-epic-friends-and-their-status?lang=en-US)를 참고했다. 이는 최소 기능 범위에 맞춘 프로젝트 설계 결정이며, 현재 로그인 성공을 의미하지 않는다.

이번 작업은 화면 및 엔진 소스 확인과 문서 기록만 수행했으며 권한 저장 성공과 클라이언트 연결은 아직 미확인이다.

## 후속 확인: 클라이언트 연결 저장 직전

사용자 화면에서 권한 탭이 녹색 `구성됨`으로 표시된 것을 확인했다. 연동된 클라이언트 탭의 선택값은 `BadmintonGameClient`이며, 해당 탭 상태는 아직 `구성되지 않음`이다. 따라서 클라이언트 선택은 확인했지만 연결 저장 완료로 기록하지 않는다.

최종 안내: 현재 선택값을 유지하고 오른쪽 아래 `변경 사항 저장`을 누른다. 상단 `연동된 클라이언트` 상태가 녹색 `구성됨`으로 바뀌는지 확인한다. 바뀌면 권한 및 클라이언트 연결 설정이 저장된 상태다. 브랜드 설정은 개발 테스트 단계에서 보류한다. 저장 후 `구성됨`으로 바뀌었다고 알려주면 UE 연결에 필요한 식별자와 로컬 비밀 설정 준비를 이어간다. 비밀 키는 채팅에 전달하지 않는다.

이번 작업은 제공된 화면 확인과 문서 기록만 수행했다. 클라이언트 연결 저장 결과, UE 로그인 및 인터넷 접속은 아직 미검증이다.

## 추가 질문: 왼쪽 허용 버튼

사용자가 왼쪽 `허용`을 눌러야 하는지 질문했다. 해당 영역은 화면에 표시된 `모바일 프리뷰`의 로그인 동의 미리보기이므로 현재 설정을 저장하기 위해 누를 필요가 없다. 오른쪽 아래 `변경 사항 저장`을 누르고 `연동된 클라이언트`가 `구성됨`으로 바뀌는지 확인하도록 답변했다. 포털 변경이나 실제 로그인 동의는 수행하지 않았다.

## 추가 질문: 애플리케이션 로고 필수 안내

사용자가 애플리케이션 로고 업로드가 필수로 표시된다고 알려왔다. 현재 로고 입력란과 오류 화면은 전달받지 않았으므로 허용 파일 형식, 크기 및 용량 제한은 아직 확인하지 못했다. 검색에서 과거 규격 자료가 발견되었지만 현재 포털 요구 규격으로 단정하지 않는다.

최종 답변: 로고가 필수라서 저장이 막히는 경우 해당 항목을 채워야 한다. 앞서 브랜드 심사를 개발 단계에서 보류할 수 있다고 안내한 것은 로고 등 저장 필수 항목까지 생략할 수 있다는 의미는 아니며 이 구분을 정정한다. 브랜드 설정에서 애플리케이션 로고 업로드 항목을 찾고, 요구 크기·형식·용량 및 오류 문구가 보이는 부분을 캡처하여 전달한다. 기존 게임 로고가 있으면 규격에 맞는 해당 파일을 사용하고, 없으면 확인된 규격에 맞춘 배드민턴 개발용 로고 제작으로 이어갈 수 있다. 로고 파일을 올리는 것과 리뷰 제출은 별도 절차다.

이번 작업은 질문 답변과 기록만 수행했다. 현재 규격 확인, 로고 제작·업로드 및 저장 성공은 미완료다.

## 후속 확인: 브랜드 초안 저장을 막는 필수 URL

사용자의 최신 화면에서 다음 상태를 확인했다.

- 권한과 연동된 클라이언트는 모두 녹색 `구성됨`이다. 이전에 미확인이었던 클라이언트 연결 저장 상태를 이번 화면으로 확인했다.
- 개발용 로고가 왼쪽 미리보기에 반영되어 있다. 브랜드 초안의 영구 저장 성공까지 의미하지는 않는다.
- 브랜드 설정은 여전히 `구성되지 않음`이다.
- 애플리케이션 웹사이트와 개인정보처리방침 URL은 비어 있고, 두 필드 모두 빨간 `필수입니다` 오류가 있다.
- 확인된 도메인 또는 하위 도메인이 없다는 안내가 표시된다.

최종 답변: 현재 브랜드 초안 저장을 막는 원인은 로고 용량이 아니라 두 필수 URL의 누락과 웹사이트 도메인 확인 미완료다. 이 화면에서 브랜드 초안을 저장하려면 실제 게임 소개 웹사이트와 개인정보처리방침 페이지를 준비하고, 포털의 `도메인을 확인` 절차를 거쳐 해당 URL을 입력해야 한다. 임의의 URL을 입력하지 않는다.

권한·클라이언트 연결은 이미 저장되었다. 브랜드 초안 저장과 별개의 상태이므로 이 두 설정을 다시 만들 필요는 없다. 개발 테스트에서 브랜드 심사를 보류할 수 있다는 이전 안내는 브랜드 초안 필수 입력값을 생략할 수 있다는 뜻이 아니며, 앞서 저장을 시도하도록 안내할 때 이 차이를 충분히 설명하지 못했음을 정정한다.

사용 가능한 본인 소유 도메인이나 게임 소개 웹사이트가 있는지 확인이 필요하다. 새 사이트 생성·배포·도메인 구매는 이번 작업에서 수행하지 않았다. 실제 UE 로그인 및 인터넷 방 생성·참가는 아직 미검증이다.

## 사용자 결정: 도메인과 웹사이트 없음

사용자가 보유한 도메인이나 게임 소개 웹사이트가 없다고 답했다. 이를 사이트 제작·배포나 도메인 구매 요청으로 해석하지 않는다.

Epic 공식 Lyra EOS 설정 안내를 다시 확인했으며 브랜드 설정은 개발 테스트에 필수가 아니라고 명시되어 있다. 현재 확인된 권한 및 클라이언트 연결의 `구성됨` 상태를 유지하고 브랜드 초안 저장은 보류한다. 웹사이트·개인정보처리방침과 도메인 확인은 공개 사용자용 브랜드 설정을 완성할 때 별도 준비한다. 브랜드 초안 저장을 위해 개발 진행까지 막을 필요는 없다.

미검토 앱의 테스트 계정에는 접근 제한이 있다. [Epic 개발 테스트 안내](https://onlineservices.epicgames.com/news/querying-for-epic-friends-and-their-status)는 조직에 포함된 계정을 이용하는 개발 테스트 경로를 설명한다. 두 번째 테스트 계정의 접근 권한은 실제 포털 상태를 확인하여 최소 범위로 구성하며, 임의의 외부 계정이 곧바로 로그인 가능하다고 안내하지 않는다. 초대나 조직 권한 변경은 이번에 수행하지 않았다.

최종 답변: 도메인이 없어도 현재 개발 테스트 준비는 이어갈 수 있다. 앞서 브랜드 저장을 계속 시도하도록 안내해 혼란을 준 점을 인정하고 브랜드 설정은 보류한다. `에픽 계정 서비스로 돌아가기`를 누른 뒤 `제품 설정 → SDK 다운로드 및 크리덴셜` 화면을 연다. Product ID, Sandbox ID, Deployment ID 등 UE 연결에 필요한 식별자 표시를 확인한다. 화면 전달 시 Client Secret은 가린다. 원격 서비스 및 UE 설정 변경은 아직 수행하지 않았다.
