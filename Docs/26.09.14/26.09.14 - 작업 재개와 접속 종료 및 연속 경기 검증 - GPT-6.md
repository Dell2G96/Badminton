## 재개 범위

이번에는 미검증이던 호스트 종료 후 복귀와 10경기 연속 종료·재경기를 우선 검증한다. 실제 Windows 녹화를 위해 설치된 OBS Studio를 확인하고 실행을 시도한다.

## 진행

- 이전 패키징 게임에서 호스트 프로세스를 종료한 후 참가자가 종료되지 않고 오프라인 배드민턴 코트로 복귀하는 테스트가 통과했다. 로그: Saved/Logs/BadmintonClient-20260914-091147-20401.log.
- 기존에는 직접 IP 모드에서 연결 종료 사유가 HUD에 남지 않았다. EOS 사용 여부와 관계없이 연결 오류 알림을 보관하고 HUD 하단에 표시하며, 새 2인 접속이 성립하면 알림을 지우도록 보완했다. 인증 방식이나 권한은 변경하지 않았다.
- 개발 전용 경기 검증 프로브에 MatchCount를 추가했다. 각 플레이어가 모든 경기 종료를 순서대로 관측하고, 마지막 재경기의 점수가 0:0인지 검사한다. 서버의 득점 로그도 경기당 11개 및 랠리 ID 중복 없음까지 검사한다.
- Test-BadmintonNetwork.ps1에 MatchCount와 CheckHostLoss 옵션을 추가했다. 10경기 연속 검사를 편도 50ms·손실 1%로 시작했다.

## 검증 결과 09시 34분

- 에디터 기반 및 Windows 패키지 각각 10경기 연속 종료·재경기 통과. 조건은 편도 50ms 지연, 송신 손실 1%. 양쪽 모두 경기 1~10의 11:0 종료와 경기 11의 0:0 재시작을 확인했으며, 서버 득점은 고유 랠리 110개였다. 로그 식별자: 20260914-091359-20402, 20260914-092251-20403.
- 갱신된 패키지에서 2인 이동 → 참가자 이탈 → 재접속 → 호스트 종료 → 참가자 오프라인 코트 복귀가 통과했다. 로그 식별자: 20260914-093139-20404. 재접속 참가자 로그에서 BADMINTON_CONNECTION_NOTICE 알림 생성과 1인 대기 복귀를 확인했다.
- F1~F5가 Unreal 기본 DebugExecBindings의 렌더링 모드 전환과 겹쳤다. 배드민턴 컨트롤러의 해당 디버그 바인딩만 제거하여 온라인 조작키를 유지했다. 합성 EOS 설정 자동화에 실제 로컬 PlayerInput 검사도 추가했으며 패키지 테스트가 통과했다.
- 게임 타깃 빌드 및 패키지 갱신 성공. 빌드 중 mt.exe 검색 실패는 해당 빌드 프로세스 PATH에 설치된 Windows SDK x64 경로를 추가하여 해결했다. 시스템 PATH는 변경하지 않았다. 최신 패키징 로그: BadmintonPackage-20260914-093051.log.
- 사용자 실행 게임의 실제 로그인 실패 결과는 EOS_Auth_WrongClient였다. 설치된 SDK eos_result.h의 의미는 인증 매개변수가 해당 클라이언트와 연결되지 않았다는 것이다. ID/비밀 키 조합 또는 EAS 연동 관계를 확인해야 하며 단일 원인을 단정하지 않는다. 오류 안내를 고정된 안전한 문구로 HUD에 추가했다. 원본 인증 로그나 비밀 값은 문서에 복사하지 않았다.
- EOS 설정 참고: [Epic 공식 Online Subsystem EOS 문서](https://dev.epicgames.com/documentation/unreal-engine/online-subsystem-eos-plugin-in-unreal-engine?lang=en-US). 합성 설정 검사는 실제 인증이나 인터넷 참가 성공을 의미하지 않는다.
- OBS Studio가 실제로 열렸으며 별도의 Badminton Tests 26.09.14 장면을 만들어 게임 창 전용 녹화를 준비 중이다.

## 녹화 시도와 사용자 중단

OBS Studio 32.2.1에서 Badminton Tests 26.09.14 장면과 윈도우 캡처 소스를 추가했다. 패키징 게임 FPS_Dell2g.exe 창만 선택하고 캔버스에 맞췄다. OBS 미리보기에서 게임 코트를 확인했다. 마이크와 데스크톱 오디오의 붉은 음소거 아이콘을 확인했다. 저장 경로는 사용자 요청에 따라 Docs/_녹화파일로 변경했다. 기존 녹화 형식 MKV는 유지했으며 완료 후 MP4로 변환할 계획이었다.

실제 녹화는 09:37:38 시작했다. 중간 파일은 Docs/_녹화파일/2026-09-14 09-37-38.mkv. 시연용 호스트 PID 35500(렌더링), 참가자 PID 25164(nullrhi), 포트 20500. 두 프로세스 모두 동일 랠리의 10회 교대 타격 검사를 통과했다. 로그는 BadmintonVideoHost-26.09.14.log와 BadmintonVideoClient-26.09.14.log다. 다만 OBS 미리보기가 대기 장면에 머무른 것으로 보여 동영상의 실제 동작 여부는 아직 검증하지 못했다.

게임 창 접근 승인 시간 초과 뒤, 사용자가 물리 Escape 키로 Computer Use를 중단했다. 도구 지시에 따라 추가 UI 조작을 중단했다. 마지막 관측 시 OBS는 녹화 중이었으며 사용자가 녹화 중단 버튼을 눌러야 한다. MP4 저장·변환·재생 검증 및 단계별 시연 영상 완료를 주장하지 않는다. 사용자가 열어 둔 EOS 게임은 종료하지 않았다.

## 남은 검증과 최종 안내

- 갱신된 게임 타깃과 패키지 검증은 통과했다. 최신 입력/알림 변경에 대한 에디터 재빌드·PIE는 사용자 실행 게임이 열린 상태여서 미완료다.
- 실제 EOS 인증 오류 해결 및 서로 다른 두 PC의 외부망 방 생성·검색·참가 검증이 필요하다.
- 최종 안내: 작업을 재개해 10경기 연속 검증, 재접속·호스트 종료 복귀 검증, F1~F5 충돌 수정과 패키지 갱신을 완료했다. EOS 클라이언트 불일치 확인은 결정 목록에 기록했다. 사용자가 Esc로 컴퓨터 제어를 중단했으며 OBS 녹화 중단과 MP4 완성은 남아 있다.
