# EOS 제품 생성 및 연결 준비 안내

작성일: 2026-09-14 · 작업 모델: GPT-6 · 프로젝트: FPS_Dell2g / UE 5.7.4

## 현재 결정과 상태

사용자가 첫 배포에 인터넷 방 생성·참가를 포함하고 Epic Online Services(EOS)를 사용하도록 결정했다. 2026-09-14 사용자 제공 화면에서 조직 `KOREA`와 제품 `Lee`가 생성되어 있음을 확인했다. Live Sandbox의 버튼은 활성화되어 있고 Stage와 Dev는 비활성화되어 있다. Deployment와 Client 구성은 아직 미확인이다. 현재 구현 중인 로컬 IP 접속은 EOS 인증·세션·P2P 검증과 별개다.

이번 프로젝트에서는 UE의 Online Subsystem EOS(OSS EOS)를 기준으로 연결할 예정이다. 제품 등록, 플러그인 구성, 로그인과 온라인 세션 설정이 필요하다. [Epic: UE 5.7 OSS EOS 안내](https://dev.epicgames.com/documentation/unreal-engine/online-subsystem-eos-plugin-in-unreal-engine?application_version=5.7)

## 사용자가 먼저 진행할 작업

1. [Epic Developer Portal](https://dev.epicgames.com/portal)에 본인 Epic 계정으로 로그인한다.
2. 사용할 Organization을 선택하거나 생성한다. 표시되는 약관과 조직 정보를 본인이 확인한다.
3. 게임용 Product를 생성한다. 표시 이름은 원하는 게임명으로 정할 수 있으며 로컬 프로젝트명 FPS_Dell2g와 같을 필요는 없다.
4. 현재 화면에서는 활성화된 **Live Sandbox 아래의 디플로이**를 클릭하여 기존 Deployment를 먼저 확인한다. EOS만 사용하는 현재 구성에서는 Stage/Dev Sandbox 활성화가 필요하지 않다. Sandbox 이름이 Live라고 해서 게임이 스토어에 출시되는 것은 아니다. 개발용 데이터 분리는 Live 내부 Deployment 구성을 확인한 후 결정한다.
5. 게임 클라이언트용 Client와 연결된 Client Policy를 구성한다. 이번 게임은 플레이어 호스트 방식이므로 클라이언트 정책의 게임 세션·로비·P2P 관련 허용 기능을 연결 단계에서 함께 확인한다.
6. 포털 화면 구성이나 필수 항목이 안내와 다르면 해당 항목의 이름과 설명을 알려준다. 임의로 공개 배포나 심사 신청을 진행할 필요는 없다.

제품·클라이언트 구성은 Epic의 시작 가이드를 기준으로 확인한다. [Epic: EOS 시작 가이드](https://dev.epicgames.com/docs/epic-online-services/eos-get-started/get-started-guide?lang=en-US)

## 로컬 연결 시 필요한 설정

| 항목 | 용도 | 공유 방식 |
|---|---|---|
| Product ID | 게임 제품 식별 | 로컬 설정 파일에 입력 |
| Sandbox ID | 개발 환경 식별 | 로컬 설정 파일에 입력 |
| Deployment ID | 사용할 서비스 데이터 환경 식별 | 로컬 설정 파일에 입력 |
| Client ID | 게임 클라이언트 식별 | 로컬 설정 파일에 입력 |
| Client Secret | 클라이언트 인증 설정 | 채팅·작업 문서에 붙이지 않고 로컬 입력 |
| Artifact Name | UE에서 읽을 설정 묶음의 이름 | 연결 시 정할 프로젝트 내부 이름 |
| Client Encryption Key | 해당 기능에서 사용하는 암호화 설정 | 필요 조건을 확인해 로컬 입력 |

필드 이름은 설치된 엔진의 `Engine/Plugins/Online/OnlineSubsystemEOS/Source/OnlineSubsystemEOS/Public/EOSSettings.h`에서 확인했다. 실제로 동작하는 구성 파일 위치와 로딩 방식은 EOS 구현 단계에 추가한다. 지금은 비밀 값을 `DefaultEngine.ini`, Git 또는 작업 문서에 추가하지 않는다.

## 로그인과 두 계정 테스트

첫 로그인은 Account Portal 방식을 사용할 계획이다. 게임에서 로그인 요청 후 표시되는 브라우저 또는 오버레이에서 사용자가 직접 인증한다. 개발 단계의 반복 테스트에는 Developer Authentication Tool 방식도 검토할 수 있다. [Epic: OSS EOS 로그인](https://dev.epicgames.com/documentation/unreal-engine/online-subsystem-eos-plugin-in-unreal-engine?application_version=5.7#login)

계정 로그인 기능을 사용할 경우 Epic Account Services 애플리케이션, 연결된 Client와 개발 중 접근 가능한 테스트 계정 구성이 추가로 필요할 수 있다. 두 명 테스트에는 서로 다른 Epic 계정을 준비하고, 동일 제품·Sandbox·Deployment에 접근할 수 있는지 확인한다. 필요 설정은 포털 상태에 맞춰 안내한다.

## 코드 연결 이후 확인할 순서

1. 설정 누락 시 게임이 종료되지 않고 구체적인 설정 안내를 표시하는지 확인한다.
2. 호스트·참가자 각각 로그인 성공을 확인한다.
3. 호스트가 2인 방을 만들고 참가자가 목록에서 찾아 참가한다.
4. EOS로 받은 접속 정보를 사용하여 같은 코트에 입장하는지 확인한다.
5. 같은 LAN 외에 서로 다른 인터넷 연결에서도 P2P 접속을 검증한다.
6. 방이 가득 참, 로그인 취소, 검색 결과 없음, 참가 실패, 호스트 종료와 재접속을 확인한다.

현재 다음 단계는 **Live 아래 디플로이 버튼을 누른 뒤 표시되는 목록을 확인하는 것**이다. 해당 화면 캡처로 기존 항목을 확인하고 다음 설정을 안내한다. Client Secret이 표시되는 화면에서는 비밀 값을 가린다.
