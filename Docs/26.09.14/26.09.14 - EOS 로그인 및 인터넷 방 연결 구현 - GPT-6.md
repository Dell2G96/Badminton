# EOS 로그인 및 인터넷 방 연결 구현

작성일: 2026-09-14 · 작업 모델: GPT-6 · UE 5.7.4

## 요청과 결과

사용자가 로컬 연결 정보 보관을 완료했다고 알렸다. `LocalSecrets/EOS.credentials.dpapi` 존재를 확인했다. 작업 도구 환경에서는 DPAPI 복호화에 실패하여 내용 검증은 보류했다. 사용자 직접 실행 런처에서 복호화하도록 구성했다. 비밀 값을 다시 입력하거나 채팅에 전달할 필요는 없다.

EOS 로그인, 인터넷 로비 생성·검색·참가·나가기 코드와 실행용 설정 런처를 추가했다. 에디터 빌드, 합성 데이터 설정 테스트와 기존 로컬 2인 이동 테스트는 통과했다. 실제 Epic 로그인 및 인터넷 접속은 아직 미검증이다.

## 변경 파일과 동작

- `FPS_Dell2g.uproject`: OnlineSubsystemEOS 활성화.
- `Source/FPS_Dell2g/FPS_Dell2g.Build.cs`: OnlineSubsystem/OnlineSubsystemUtils 의존성 추가.
- `Source/FPS_Dell2g/Badminton/BadmintonOnlineSubsystem.h/.cpp`: GameInstanceSubsystem에서 Account Portal 로그인과 비동기 세션 작업을 관리한다. 맵 이동 시에도 상태를 유지하고 종료 시 델리게이트를 해제한다. 중복 요청 및 로그인 전 요청을 제한하고 실패 시 방 정리를 시도한다.
- 방은 2인 공개 EOS 로비이며 프로토콜 필터 BADMINTON_PROTOCOL=1을 사용한다. 빈 자리가 있는 호환 방만 표시한다. 생성 후 Listen Server로 이동하고 참가 시 EOS가 반환한 접속 문자열을 사용한다.
- `BadmintonPlayerController`, `BadmintonHUD`: F1 로그인, F2 방 생성, F3 검색, F4 첫 번째 방 참가, F5 나가기와 상태·방 목록 표시를 추가했다. 다른 번호는 콘솔 `BadmintonEOSJoin <index>`로 참가한다. 현재는 개발용 UI다.
- `Scripts/Start-BadmintonEOS.ps1`, `Start-BadmintonEOS.cmd`: 사용자가 탐색기에서 직접 실행하는 EOS 게임 런처.
- `Source/FPS_Dell2g/Tests/BadmintonEOSConfigTests.cpp`: 실제 자격 증명을 사용하지 않고 런처 설정이 Unreal에 적용되는지 확인한다.
- 기존 기본 실행과 로컬 IP 경로는 유지한다. EOS는 전용 런처의 -BadmintonEOS와 실행별 설정을 사용할 때 활성화한다.

## 로컬 비밀 설정과 권한

런처는 사용자 환경에서 DPAPI 파일을 복호화해 `LocalSecrets/Run-<무작위값>/Engine.ini`를 생성하고 해당 폴더 접근을 현재 Windows 사용자로 제한한다. 실행 중에는 UE가 읽는 평문 설정이 이 폴더에 존재한다. 명령행에는 -EngineIni 파일 경로만 전달하고 비밀 값은 전달하지 않는다. Default*.ini, Docs, Git에는 비밀 값을 쓰지 않는다.

게임 종료 후 런처가 해당 실행의 Engine.ini와 빈 폴더만 제거하며 암호화 원본은 보존한다. 런처를 강제 종료하면 정리되지 않을 수 있으므로 게임 종료 전 런처를 닫지 않는다. 플레이어/타이틀 저장소 미사용 조건에서 Epic 문서의 기본 ClientEncryptionKey를 사용한다. 저장소 기능 도입 시 전용 키 설정이 필요하다.

로그인 요청 권한은 BasicProfile만 사용한다. 게임에서는 친구 조회, Presence 참가와 소셜 오버레이를 사용하지 않는다. 다만 UE 내부에는 로그인 후 친구 목록 조회 시도가 있어 부가적인 권한 오류가 생기는지 실제 로그인 때 확인해야 한다. 아직 이 이유만으로 추가 권한을 요청하지 않는다.

## 검증

1. UHT/Development Editor 빌드 통과. 테스트 플래그를 UE 5.7의 EditorContext/ClientContext로 맞추는 컴파일 수정이 있었다.
2. `Start-BadmintonEOS.ps1 -ConfigurationTest`와 `FPS_Dell2g.EOS.Configuration` 자동화 테스트 통과. 합성 값만 사용하여 실제 암호화 자격 증명은 읽지 않았다.
3. 첫 설정 테스트에서 generated Engine.ini에 Default*.ini용 +/! 배열 표기를 사용하면 아티팩트·권한·NetDriver가 반영되지 않음을 발견했다. 접두사 없는 생성 설정 키로 수정한 후 EOS 기본 서비스, BasicProfile 단일 권한, 합성 아티팩트, P2P 드라이버·소켓 설정을 모두 검증했다.
4. 합성 설정으로 EOS 서브시스템 초기화 및 로그인 대기 상태 로그를 확인했다. 실제 인증 성공과는 구분한다.
5. 설정 테스트 종료 후 실행별 임시 폴더가 남지 않은 것을 확인했다.
6. 기존 로컬 별도 프로세스 2인 이동·ASC·준비 테스트를 편도 지연 50ms·패킷 손실 1% 조건에서 통과했다. 세 번째 참가자는 BadmintonRoomFull로 거절되었다. EOS 외부망 테스트는 아니다.
7. PowerShell 런처 구문 분석과 git diff --check, LocalSecrets의 Git 제외 상태를 확인했다.

로그: `Saved/Logs/BadmintonEOSBuild.log`, `Saved/Logs/BadmintonEOSConfigTest.log`, `Saved/Logs/BadmintonHost-20260914-061916-18887.log` 및 같은 실행의 Client/정원 테스트 로그.

## 사용자 실행 순서와 최종 안내

1. 탐색기에서 `D:\_Projects\FPS_Dell2g\Start-BadmintonEOS.cmd`를 더블클릭한다.
2. 게임 화면을 클릭하고 F1을 누른다. 브라우저의 Epic 로그인과 동의는 사용자가 직접 진행한다.
3. 게임에 `Login successful`이 표시되는지 알려준다. 실패하면 게임 상태 문구를 전달하고 비밀 키나 브라우저 토큰을 전달하지 않는다.
4. 이후 두 번째 Epic 계정의 개발 앱 접근 권한을 준비한다. 호스트 F2, 참가자 F3 → F4 순서로 실제 2인 접속을 검증한다.

## 미완료와 시연 영상

실제 계정 로그인·취소·재시도, 두 계정 EOS 방 접속, 외부망 P2P, 방 가득 참/호스트 종료/재접속은 미검증이다. 브랜드 설정은 도메인 부재로 보류되어 개발 앱에 접근 가능한 테스트 계정이 필요하다. 패키징, 최종 UI 및 경기 규칙·샷 확장도 기존 미완료 항목으로 유지한다.

단계별 Windows 시연 영상은 미완료다. 현재 도구 환경에서 사용자 화면에 띄운 창을 신뢰성 있게 조작하지 못했고 이번 검증은 화면 없는 설정·네트워크 테스트였다. 다음 실제 실행 때 Windows 녹화 프로그램으로 `Docs/_녹화파일/26.09.14 - EOS 로그인 및 방 접속 테스트 시연 - GPT-6.mp4`를 녹화하고 재생 확인해야 한다. 인증 화면과 비밀 값은 녹화하지 않는다. 에디터 PIE 직접 조작도 아직 미검증이다.
