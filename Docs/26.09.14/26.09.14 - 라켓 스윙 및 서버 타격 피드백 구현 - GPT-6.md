## 요청 및 범위

사용자 요청: 다음 작업 진행. 이전 HUD 단계에 이어 라켓 스윙·서버 타격 피드백·셔틀콕 추적 표시를 구현한다. EQS/EOS 테스트 보류를 유지한다. 기존 최종 에셋 결정 없이 기본 도형을 사용한다.

## 진행 기록

- AGENTS.md, 기존 변경 및 최근 Git 이력, 캐릭터·셔틀·GAS·HUD 코드를 확인했다. 관련 없는 변경은 보존한다.
- 기존 기본 도형으로 라켓 프레임·그립·스트링을 구성한다. 모든 라켓 파트는 충돌과 오버랩을 끄며 기존 캡슐·서버 타격 판정은 유지한다.
- GAS 발동 승인 후 입력 소유자는 즉시 스윙을 시작하고 서버는 비소유자에게 스윙 종류·랠리·시퀀스·시각·지속 시간을 복제한다. 소유자에게는 이 상태를 복제하지 않아 예측/서버 연출 중복을 막는다.
- 서버에서 판정한 타격 성공 또는 헛스윙 결과를 소유자에게 보내 1.1초간 표시한다. 오래된 결과와 다른 랠리의 안내는 표시하지 않는다. 능력 발동 자체가 거절된 입력과 헛스윙을 구분한다.
- 셔틀콕의 현재 표시 위치에 마름모 표시와 최근 6개 샘플의 짧은 잔상을 그린다. 이는 위치 추적 연출이며 예상 착지점이나 타격 판정이 아니다. 샷·랠리 전환 시 잔상을 초기화한다.
- Presentation 자동 검사를 추가하여 같은 랠리 10회 교대 타격 후 각 화면에서 자기 스윙 5회·상대 스윙 5회·타격 성공 결과 5회를 확인한다.

## 검증 및 미완료

에디터/게임 빌드, 2인 연출·능력 검사 및 렌더링·패키징을 진행한다. 네이티브 앱 제어가 비활성화되어 PIE 수동 조작과 Windows MP4 녹화는 수행할 수 없으며 별도 미완료로 기록한다. 기존 OBS 세션은 조작하지 않는다.

- 빌드 갱신: 첫 빌드에서 테스트 반복 변수 이름이 AController::Character 멤버를 가리는 C4458 오류를 수정했다. 재빌드 성공(Saved/Logs/BadmintonPresentationBuild.log).
- 복제 보완: 스윙 상태가 GameState의 새 랠리보다 먼저 도착하면 다음 Tick에서 재시도한다. 과거 랠리·만료 스윙은 재생하지 않는다.
- 검증 확장: 동일 타격 결과의 중복 도착과 이전 랠리 결과가 현재 안내를 덮어쓰지 않는지도 Presentation 검사에 포함했다. 편도 50ms·손실 1%의 연출 및 기존 능력 검사를 시작했다.

- 2인 검증 통과: 편도 50ms·손실 1%에서 호스트/참가자 모두 localSwings=5, remoteSwings=5, contacts=5. 같은 랠리의 10회 교대 타격 및 오래된/중복 타격 안내 차단 포함. 로그: BadmintonHost/Client-20260914-113437-20520.log.
- 능력 회귀 검사 통과: 양쪽 비용·스태미나 부족·오래된 입력·연속 입력·대시 이동. 드롭/스매시 헛스윙 contact=0 결과가 양쪽 소유자에 전달되는 것도 로그에서 확인했다. 로그: BadmintonHost/Client-20260914-113438-20521.log.
- 에디터와 게임 대상 빌드 성공. 스윙과 타격 안내가 실제 화면에 표시되는 순간을 검토하기 위해 기존 개발용 캡처에 BadmintonCaptureOnContact 옵션을 추가했다. BadmintonCapture와 함께 사용하면 시작 후 5초 이상 지난 첫 타격 성공 안내 순간을 저장한다. 일반 플레이/Shipping 동작에는 영향을 주지 않는다.

- 최종 캡처 옵션 포함 에디터/게임 빌드 모두 성공. Windows 패키지 조립 성공(Saved/Logs/BadmintonPackage-20260914-113822.log). 엔진 staging 임시 파일 쓰기에 앞서 허용된 표준 패키징 확장 실행을 사용했다.
- 기본 도형은 이미 쿠킹된 Cube/Cylinder 에셋을 재사용해 별도 바이너리 에셋 변경 없이 패키지에 반영했다. 새 게임 exe와 패키지 exe의 SHA256 일치를 확인했다.

## 재실행

프로젝트 루트에서 다음 명령으로 연출 중복 검사를 실행할 수 있다.

```powershell
./Scripts/Test-BadmintonNetwork.ps1 -TestKind Presentation -Port 20520 -OneWayLagMs 50 -PacketLossPercent 1
```

패키지 기준 검사는 -GameExecutable에 Saved/Packages/BadmintonMVP/Windows/FPS_Dell2g/Binaries/Win64/FPS_Dell2g.exe의 절대 경로를 전달한다. RenderOffscreen 시각 검토에는 게임 인수 -BadmintonCapture -BadmintonCaptureOnContact를 사용하며 Saved/Screenshots/BadmintonPrototype.png에 저장한다. 사람의 플레이는 기존 Start-BadmintonPackage.cmd를 사용한다.

## 제한 및 남은 작업

- 기본 도형 기반 프로토타입 라켓 연출이다. 최종 캐릭터 스켈레탈 애니메이션·라켓 그립·손 위치 정렬·사운드는 후속 작업이다. 타격은 기존 서버 거리/높이/타이밍 조건을 사용하며 라켓 메시 접촉과 완전히 일치하도록 조정한 단계는 아니다.
- 원격 스윙은 서버 시각 기준 남은 구간을 재생한다. 지속 시간보다 늦게 도착하거나 중간 상태가 병합된 연출은 생략될 수 있으며 경기 판정에 영향은 없다. 이번 검사 조건에서 원격 스윙 5회를 모두 관측했다.
- 헛스윙 문구는 서버 승인된 능력의 무접촉 결과다. 스태미나 부족 등 발동 자체 거절은 기존 능력 카드 상태로 확인한다.
- EQS 및 실제 EOS 인증/외부망 테스트 보류를 유지했다.
- PIE 수동 조작 및 Windows MP4 시연 녹화는 네이티브 앱 제어 비활성화로 미완료다. 스크린샷은 실제 RenderOffscreen 결과이며 영상으로 표시하지 않는다.
- PowerShell 구문 검사, git diff 공백 검사, 변경 소스 줄 끝 공백 검사를 수행했다. 기존 Docs Git 제외 규칙은 유지했으며 커밋/외부 게시를 수행하지 않았다.
