# EOS 로컬 연결 정보 입력 준비

작성일: 2026-09-14 · 작업 모델: GPT-6

## 요청과 확인 상태

사용자가 SDK 다운로드 및 크리덴셜 화면을 전달했다. 제품 Lee, BadmintonGameClient, Live Sandbox, Live Deployment가 표시된다. 식별자는 사용자에 의해 가려져 있고 비밀 키는 마스킹되어 있다. 가려진 값을 복원하거나 추측하지 않았다. 애플리케이션 이름도 이 화면에서는 Lee로 표시되어 브랜드 초안의 Badminton 이름 저장을 확정하지 않는다. 이전 화면에서 권한과 연동된 클라이언트의 구성됨 상태는 확인했다.

## 수행 내용과 변경 파일

- `Scripts/Set-BadmintonEOSCredentials.ps1`: 사용자가 로컬에서 5개 값을 입력하는 Windows Forms 창을 작성했다. 입력값을 네트워크로 전송하지 않는다.
- 전체 JSON 연결 정보를 Windows DPAPI 방식으로 암호화하여 `LocalSecrets/EOS.credentials.dpapi`에 보관한다. 같은 Windows 사용자와 PC에서의 복호화를 전제로 하며 다른 PC로의 복사 사용은 지원하지 않는다. 보관 성공 시 입력란을 지운다. 기존 파일 교체 시 창에서 확인한다.
- `.gitignore`에 `/LocalSecrets/`를 추가했다. 비밀 값을 DefaultEngine.ini, Docs, 소스, 명령행에 입력하지 않는다.
- 이후 UE 연결에 사용할 내부 ArtifactName은 BadmintonDev, 로그인 요청 범위는 BasicProfile로 보관하도록 했다. 이것은 연결 준비 데이터이며 UE 프로젝트 적용은 아직 수행하지 않았다.

## 사용자 입력 안내와 최종 답변

`배드민턴 EOS - 이 PC에 연결 정보 보관` 창을 실행했다. 이 창에 포털 복사 버튼으로 다음 5개 값을 넣고 `암호화하여 보관`을 누른다.

| 입력 항목 | 포털에서 복사할 값 |
|---|---|
| 제품 ID | 제품 Lee의 제품 ID |
| 샌드박스 ID | Live의 샌드박스 ID |
| 디플로이 ID | Live Deployment의 디플로이 ID |
| 클라이언트 ID | BadmintonGameClient의 클라이언트 ID |
| 클라이언트 비밀 키 | BadmintonGameClient의 비밀 키, 또는 사용자가 보관한 값 |

애플리케이션 ID는 이 입력 창에서 사용하지 않는다. 포털의 헤더 파일 크리덴셜 사용 버튼은 누를 필요가 없다. 비밀 키가 포함된 화면이나 값을 채팅에 전달하지 않고 보관 후 `로컬 보관 완료`라고 알려준다.

## 검증과 미완료 사항

- PowerShell 구문 분석 통과.
- 실제 자격 증명이 아닌 합성 데이터로 Windows DPAPI 암호화·복호화 일치와 암호문 내 평문 부재를 확인했다. 테스트는 자격 증명 파일을 만들지 않았다.
- git check-ignore로 대상 경로가 Git에서 제외됨을 확인했다. git diff --check 통과.
- 입력 창 프로세스를 실행했다. 실제 사용자의 값 입력·보관 완료는 아직 미확인이다.
- 최초 Windows PowerShell 실행은 실행 정책으로 차단되었다. 실행 정책을 변경하지 않고 검증에 사용한 번들 PowerShell의 `pwsh.exe -NoProfile -STA -File ...`로 다시 실행하여 프로세스 PID 22276이 유지됨을 확인했다. 비밀 값이 표시되는 UI 내용은 읽지 않았다.
- 이번 작업은 연결 정보 준비 도구 추가다. UE 코드 변경이나 게임 단계 테스트는 수행하지 않았다. 입력 창은 자격 증명을 다루므로 녹화하지 않았고 게임 시연 영상도 이번에 생성하지 않았다.
- EOS 로그인·세션·P2P 구현과 게임 접속 검증은 아직 미완료다. 암호화 파일 보관만으로 UE가 EOS에 연결되지는 않는다.

## 입력 창 표시 문제 후속 처리

사용자가 입력 창의 위치를 물었다. 최초 숨김 실행 프로세스 PID 22276에는 메인 창 제목이 없었고 Windows 창 목록에서도 입력 창을 찾지 못했다. 프로세스 실행만으로 창이 사용자에게 보인다고 판단한 앞선 안내를 정정한다.

해당 작업에서 실행한 기존 프로세스를 종료하고, 사용자에게 입력 창을 표시하기 위해 동일 스크립트를 WindowStyle Normal로 다시 실행했다. 새 프로세스 PID 4588의 MainWindowTitle이 `배드민턴 EOS - 이 PC에 연결 정보 보관`인 것을 확인했다. 입력값이나 비밀 키는 읽지 않았다. 컴퓨터 사용 도구의 창 목록에는 여전히 해당 창이 없어 자동으로 앞으로 가져오지는 못했다.

최종 안내: 입력 창을 보이는 방식으로 다시 실행했고 창 제목을 확인했다. Alt+Tab을 눌러 `배드민턴 EOS - 이 PC에 연결 정보 보관` 창을 선택한다. 이것은 Edge 안의 창이 아니라 별도 Windows 창이다. 포털 값 5개를 입력한 뒤 `암호화하여 보관`을 누른다. 실제 사용자가 창을 볼 수 있는지와 입력 완료는 아직 확인되지 않았다.

## 사용자 직접 실행 방식으로 변경

사용자가 여전히 입력 창이 보이지 않는다고 알렸으며 제품·샌드박스·디플로이·클라이언트 ID 4개를 제공했다. 비밀 키는 제공하지 않았고 처리 방법을 물었다. 제공한 ID는 Git에서 제외된 `LocalSecrets/EOS.identifiers.json`에 보관하고 입력 창의 해당 필드가 자동으로 채워지도록 수정했다. 문서에는 식별자 원문을 중복 기록하지 않는다.

프로젝트 루트의 `Open-EOS-Setup.cmd`를 추가했다. 사용자가 탐색기에서 직접 더블클릭하면 자신의 화면에서 번들 PowerShell로 입력 스크립트를 실행한다. 시스템 실행 정책은 변경하지 않는다. 런처는 이 PC의 확인된 실행 파일 경로를 사용하며 경로가 사라지면 오류를 안내한다. 이전에 자동 실행한 작업 소유 프로세스는 종료하고 더 이상 같은 방식으로 창을 띄우지 않는다.

검증: PowerShell 구문 분석, 사용자 제공 식별자 형식, Git 제외 여부를 확인했다. 직접 더블클릭 후 실제 창 표시와 비밀 키 보관 완료는 아직 사용자 확인이 필요하다.

최종 답변: 비밀 키를 채팅에 입력하지 않는다. 탐색기에서 `D:\_Projects\FPS_Dell2g\Open-EOS-Setup.cmd`를 더블클릭하고, 자동 입력된 ID 4개를 확인한다. 생성 시 안전하게 보관한 Client Secret을 마지막 비밀 키 칸에 붙여 넣은 뒤 `암호화하여 보관`을 누른다. 비밀 키를 보관하지 못했고 포털에서도 다시 복사할 수 없다면 재발급 절차가 필요하므로 키 원문 대신 `키를 보관하지 못했어`라고 알려달라고 안내한다. 이번에 키를 생성·재발급·전송하거나 실제 EOS에 연결하지 않았다.
