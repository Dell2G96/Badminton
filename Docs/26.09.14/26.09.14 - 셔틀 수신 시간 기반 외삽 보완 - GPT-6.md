## 조사 근거와 범위

로컬 UE 5.7의 Engine/Source/Runtime/Engine/Private/GameStateBase.cpp 144~192행을 확인했다. GetServerWorldTimeSeconds는 로컬 World 시간에 수신 시 계산한 delta를 더한다. OnRep_ReplicatedWorldTimeSecondsDouble은 수신 서버 타임스탬프에서 현재 로컬 시간을 빼고 평균·평활 처리하며 전송 지연을 별도 보정하지 않는다. 서버 시간 갱신 기본 주기는 0.1초다. 셔틀 PublishState는 별도로 최대 약 30Hz에서 상태 시각을 기록한다.

따라서 GameState 추정 시각이 최신 셔틀 상태보다 뒤일 수 있으며 기존 clamp(raw age, 0, 150ms)는 그동안 외삽을 0으로 고정한다. 각 실행의 음수 값 중 전송·복제 주기·프레임 순서가 차지하는 비중은 분리 측정하지 않았다. Tick 순서가 단독 원인이라고 단정하지 않으며 엔진 소스나 전역 서버 시계를 수정하지 않는다.

## 변경 설계

- 매 OnRep_Flight에서 로컬 게임 시각을 기록한다. 새로운 샷·랠리·정지 상태도 이 수신 기준을 새로 설정한다.
- 표시 외삽 시간은 clamp(max(기존 원시 상태 나이, 수신 후 로컬 게임 경과 시간), 0, 150ms)로 계산한다. 수신 후 실제 흐른 시간은 해당 상태 나이의 하한으로 사용한다.
- 유효한 기존 서버 시각 추정이 더 큰 나이를 제공하면 계속 사용한다. 일시 정지에는 게임 시각이 멈추며 장기 미수신에는 150ms 상한을 유지한다.
- 원시 음수 나이는 로그에 그대로 보존한다. receipt_ms, present_ms, floor로 수신 후 시간·사용한 외삽 시간·하한 사용 여부를 추가한다. 보고서는 이전 로그 형식도 읽고 없는 지표는 미측정으로 표시한다.
- 이 변경은 전송 시간 추정, 서버 시계 동기화, 서버 타격 지연 보상을 구현하지 않는다. 서버 판정·스태미나·득점·RPC·복제 속성은 변경하지 않는다.

## 후속 작업과 최종 안내

1. 동일 시점 서버 좌표를 기준으로 표시 지연·위치 오차를 측정하고, 필요하다면 독립 시계 왕복 측정이나 스냅샷 보간 정책을 설계한다. 단순히 엔진 Ping의 절반을 더해 정확한 동기화라고 주장하지 않는다.
2. 사람의 실제 마우스 타격·PIE·별도 PC/LAN·MP4는 미완료다. EOS/EQS 및 외부망 테스트 보류를 유지한다.
3. 첫 능력 프로브 실패 원인은 이전 기록 그대로 미확정이다. 이번 변경은 해당 비용 경로를 수정하지 않았다.
4. 이번 작업에서 커밋·외부 게시·OBS 조작을 수행하지 않았다. 검사 도구가 자신이 시작한 게임 프로세스를 정리했다. Docs·에셋의 기존 Git 제외 규칙은 유지했다.

최종 안내: 음수 시간 추정 상황에서도 셔틀 외삽이 진행되도록 수신 후 경과 시간을 하한으로 사용하고 최종 패키지에 반영했다. 자동화 10개, 세 지연/손실 조건의 랠리, 최종 패키지 조준·능력·경기 종료·재경기 및 화면 검증이 통과했다. 서버 시계 자체 동기화와 실제 서버 위치 정확도 개선은 완료로 표시하지 않는다. 전체 단계별 작업 기록에도 단계 17을 추가했다.
