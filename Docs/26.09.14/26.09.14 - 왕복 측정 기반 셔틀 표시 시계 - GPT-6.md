## 요청 및 진행

작업 시작 시 AGENTS.md, Git 상태·최근 이력, Controller·셔틀 표시·계측·검사 코드를 확인했다. 왕복 시각은 셔틀 표시용으로만 사용한다. 서버 GameState 시간·타격·득점 판정을 변경하지 않는다.

## 구현 설계

- 로컬 원격 참가자의 PlayerController가 약 1초마다 소유권이 있는 Unreliable 서버 RPC를 보내고, 서버는 현재 게임 시각을 클라이언트 RPC로 돌려준다. 서버는 컨트롤러당 최소 0.25초 간격으로 응답을 제한한다.
- 요청 시퀀스가 현재 미완료 요청과 같은 응답만 한 번 수용한다. RTT는 로컬 단조 시계의 경과 시간이다. 서버에 클라이언트가 주장하는 타격 시각을 전달하지 않는다.
- RTT의 절반을 대칭 전송/큐 지연의 근사로 더해 서버 게임 시각과 로컬 게임 시각의 offset을 구한다. 이것은 정밀한 외부 시계 동기화가 아니며 비대칭 경로와 프레임 처리 지연 오차가 남는다.
- 최근 8초·최대 8개 표본 중 가장 작은 RTT를 선택한다. 이미 유효한 시계의 보정은 응답당 5ms로 제한한다. 첫 유효 표본 또는 만료 후에는 새 기준을 설정한다.
- RTT가 1초를 넘거나 값이 잘못된 응답, 게임 시각과 실제 경과가 100ms 넘게 어긋나는 정지/시간 변경 구간은 무효화한다. 3초간 유효 응답이 없으면 기존 GameState+수신 시간 하한 방식으로 돌아간다.
- 표시 외삽의 수신 시간 하한과 150ms 상한은 유지한다. 최종 기본은 기존 Legacy다. 개발 비교 옵션 BadmintonRoundTripClock으로 새 시계를 선택하고 BadmintonLegacyClock이 함께 있으면 기존 방식이 우선한다. Shipping에서는 후보 시계를 끈다. 검사 스크립트의 ClockMode=Legacy/RoundTrip으로 같은 빌드 A/B를 수행한다.
- 기존 age_ms는 엔진 기준 값을 유지한다. sync_age_ms·clock_rtt_ms·clock_synced로 표시 시계 선택을 별도 기록하고 공통 시각 추적 헤더에 모델 이름을 추가한다.

## 검증 계획

대칭 지연·큐 이상치, 순서가 바뀐/중복/비유한 응답, 만료·일시 정지·월드 시각 초기화, 보정 상한·표본 만료를 자동화로 검사한다. 같은 빌드에서 0ms/0%, 50ms/1%, 75ms/3% 각각 Legacy/RoundTrip을 순차 비교한다. 기능 회귀·패키징·패키지 기본 실행·화면 검사를 이어서 수행한다.

PIE 직접 조작·사람의 마우스 타격·별도 PC/LAN·외부망·MP4는 현재 네이티브 앱 제어가 비활성화된 환경에서 수행하지 못하며 미완료로 남긴다. 추정 시차 개선을 실제 디스플레이 지연이나 타격 지연 보상 완료로 표시하지 않는다.

## 진행 중 확인

최초 빌드에서는 테스트용 Infinity 상수가 UE TNumericLimits에 없어 컴파일이 실패했다. 표준 C++ numeric_limits로 수정한 뒤 BadmintonClockEditorFinalBuild.log에서 에디터 빌드가 성공했다. 런타임 시계 구현은 해당 최초 빌드에서도 컴파일됐으며 테스트 기대값을 완화하지 않았다. RPC 추가로 UHT 파일 3개가 갱신되어 최종 패키지는 정상 빌드/쿠킹으로 검증한다.

정지 감지는 로컬 게임 경과와 실제 경과의 차이에 대한 검사다. 서버만 별도로 정지하거나 시간 배율을 다르게 운용하는 모드까지 검증한 것은 아니다. 현재 실시간 배드민턴 프로토타입의 양쪽 게임 시간 배율 1을 기준으로 한다.

### 실패에서 확인한 사실

- Legacy 최초는 랠리 1의 sequence 3 다음 리턴이 성립하지 않아 1:0 득점 후 랠리 2에서 Aim FAIL이 났다. 당시 다음 리턴의 서버 TryShot 기록은 없으므로 거리/높이 거절로 단정할 수 없다.
- RoundTrip 최초는 첫 서브 이후 리턴이 성립하지 않아 같은 후속 Aim FAIL이 났다. 이 실행도 누락 원인을 확정하지 못했다.
- RoundTrip 재검사는 랠리 1의 sequence 3 이후 참가자 리턴이 서버에서 `TooLow`, 높이 50.723cm로 거절됐다. 이후 득점과 새 서브가 진행됐다. 늦은 도착의 전 구간 원인이나 시계 변경과의 인과관계는 확정하지 않았다.
- Aim 프로브는 0점 기준 서브 목표와 연속 10샷을 기대한다. 따라서 중간 득점 후의 `replicated aim/target` 문구만으로 조준 데이터가 손상됐다고 결론 내리지 않는다. 앞선 랠리 중단 때문에 전체 검사는 실제로 실패다.
- 마지막 실패 실행의 `capped` 3개는 계산된 원시 나이가 150ms를 넘어 제한된 표본이다. 실제 적용 외삽이 150ms를 넘었다는 뜻은 아니다.
- 실패 로그와 별도 분석 보고서는 모두 보존했다. 보고서 생성 성공을 게임 검사 성공으로 바꾸지 않았다. 성공할 때까지 재시도하지 않고 후보의 기본 적용을 보류했다.

각 실행의 원본은 `Saved/Logs/BadmintonHost-실행ID.log`, `BadmintonClient-실행ID.log`이며 같은 날짜 폴더의 `네트워크 계측 BadmintonHost-실행ID`, `동시 위치 비교 BadmintonHost-실행ID` 문서가 상세 통계다.
