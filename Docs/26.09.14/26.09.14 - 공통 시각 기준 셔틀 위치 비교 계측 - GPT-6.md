[이전 수신 시간 보완](<26.09.14 - 셔틀 수신 시간 기반 외삽 보완 - GPT-6.md>)은 로컬 목표와의 거리만 측정했다. 이번에는 같은 PC에서 실행한 서버·참가자 위치를 공통 시각으로 결합한다.

UE 5.7의 Engine/Source/Runtime/Core/Public/Windows/WindowsPlatformTime.h에서 FPlatformTime::Seconds가 QPC×초 변환 계수+고정 상수를 반환하는 것을 확인했다. [Microsoft QPC 문서](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps)는 같은 컴퓨터의 프로세스 간 카운터 비교를 설명한다. 다른 PC의 시각을 이 방법으로 맞출 수 있다고 가정하지 않는다.

## 설계 및 진행

- PositionTrace 옵션은 같은 PC의 두 프로세스에 실행별 GUID를 전달한다. Windows 개발 실행에서만 프레임 종료 위치와 QPC 시각을 로그에 기록한다. Shipping에서는 기록하지 않는다.
- 서버·참가자 로그의 실행 GUID, 시계 종류, 머신 이름을 대조하며 분석 시 SameMachine 확인이 필요하다. 게임 연결·RPC·복제 속성과 표시 알고리즘은 변경하지 않는다.
- 서버의 전후 표본 사이를 선형 보간해 참가자 표본 시각의 기준 위치를 근사한다. 50ms보다 긴 구간과 샷·랠리·비행 상태 전환, 충돌 구간은 제외한다.
- 같은 샷의 과거 300ms 궤적에서 표시 위치와 가장 가까운 지점도 찾는다. 그 시차는 궤적을 뒤따르는 정도이며 패킷 RTT나 입력→화면 지연을 직접 측정한 값은 아니다.
- 샷 전환으로 서버와 참가자의 상태가 다른 표본을 별도 집계하고 일반 비행 오차에 섞지 않는다. 첫 TEST PASS/FAIL까지 구간을 고정한다.
- 합성 궤적에서 알려진 위치 오차·시간차와 경계 제외를 검사한 뒤 3개 지연/손실 조건, 빌드·패키지를 검증한다.

PIE 직접 조작·실제 마우스 플레이·별도 PC/LAN·외부망과 MP4는 현재 제어 환경에서 수행할 수 없어 미완료로 남긴다. OBS를 조작하지 않는다.

## 합성 검사와 빌드

첫 합성 검사에서 100ms 시차가 90ms로 산출되는 실패를 확인했다. PowerShell에서 Math.Clamp/Min/Max에 정수 경계값을 전달하면 선택된 오버로드가 보간 비율을 정수로 반올림하는 경로가 있었다. 비율과 경계값을 double로 명시한 뒤 알려진 100ms 시차·3cm 횡오차, 동시 좌표 0오차, 300ms 탐색 상한, 샷 불일치·범위 밖·긴 프레임·충돌 경계 제외, 정지 궤적·큰 QPC 원점·다른 실행 차단 검사가 모두 통과했다. 검사 기대값과 허용 오차를 완화하지 않았다. 이 오류는 실측 보고서 생성 전에 수정했다.

에디터 빌드는 BadmintonPositionEditorBuild.log에서 성공했으며 UHT 생성 파일 변경은 0개다. 개발 추적 코드·분석 스크립트 외 서버 판정과 표시 보간은 변경하지 않았다.

## 실행 방법

프로젝트 루트 D:/_Projects/FPS_Dell2g에서 실행한다.

```powershell
# 동일 PC의 독립 프로세스 Aim 랠리, 기존 계측과 공통 시각 위치 비교
./Scripts/Test-BadmintonNetwork.ps1 -TestKind Aim -Port 20903 -OneWayLagMs 50 -PacketLossPercent 1 -NetMetrics -PositionTrace -GameExecutable 'D:/_Projects/FPS_Dell2g/Saved/Packages/BadmintonMVP/Windows/FPS_Dell2g/Binaries/Win64/FPS_Dell2g.exe'
```

## 완료 결과와 후속 작업

최종 패키지 기본 실행(20260914-144557-20904, 편도 50ms/손실 1%)은 양쪽 11:0 경기 종료·0:0 재경기와 11개 고유 랠리 득점을 통과했다. 이 실행의 위치 추적 및 기존 계측 로그는 모두 0건이었다. 최종 조준·경기 로그에 테스트 실패·Fatal·Assertion·Ensure 실패 마커가 없고 검사 프로세스가 모두 정리된 것을 확인했다.

이번 변경은 진단 로그와 오프라인 분석이다. 화면이나 플레이 알고리즘을 바꾸지 않아 새 렌더링 캡처와 사람의 플레이 검사는 수행하지 않았다. PIE·실제 마우스·별도 PC/LAN·MP4는 미완료이고 EOS/EQS·외부망 보류를 유지한다. 이전 일회성 능력 검사 실패는 원인 미확정 이력으로 남기며 이번에는 비용 코드를 수정하거나 해결했다고 표시하지 않는다. 커밋·외부 게시·OBS 조작은 수행하지 않았다.

다음 구현 후보는 제한된 왕복 시각 측정으로 셔틀 스냅샷의 전송 나이를 추정하고, 현재 수신 시간 하한 방식과 같은 위치 비교 도구로 A/B 검증하는 것이다. 이번 결과만으로 Ping의 절반을 무조건 더하거나 서버 타격 판정을 완화하지 않는다. 측정 오차·프레임 위상·샷 전환 지연을 함께 확인하며 표시 시계와 서버 타격 권한은 분리한다.

최종 안내: 같은 PC의 공통 시각을 사용하는 셔틀 위치 비교 계측을 추가하고 최종 패키지에 반영했다. 세 지연/손실 조건의 랠리, 합성 분석 검사, 배드민턴 자동화 10개, 최종 패키지의 조준·경기 종료·재경기가 통과했다. 편도 50ms/손실 1% 에디터 실행의 위치 차이 중앙값은 약 48.5cm, 과거 궤적 추종 시차는 약 76ms였다. 이는 연속 서버 위치와 실제 화면 지연의 직접 실측이 아닌 공통 시각 표본 보간 및 궤적 기반 추정이다. 전체 작업 단계별 문서에 단계 18도 추가했다.
