# 3인칭 낙하 타이밍 타격 전환

- 작업일: 26.09.21 Asia/Seoul. 모델: GPT-6.
- 요청: 1인칭 플레이를 보류하고 3인칭에서 셔틀콕이 내려오는 타이밍에 맞춰 타격하는 방식으로 물리와 조작을 보완하고 테스트.
- 기존 미커밋 변경을 유지한다. 이전 분할 화면 기록: [작업 기록](<26.09.21 - 3인칭과 1인칭 동시 분할 화면 - GPT-6.md>).

## 설계와 진행

- 기본 화면은 전체 3인칭. 마우스로 라켓을 직접 일치시키는 검증을 제거하고, WASD 위치·선택 샷별 높이·하강 타이밍을 서버가 판정한다.
- 마우스는 상대 코트 목표 지점 조절에 사용한다. 좌클릭은 선택한 샷을 시도한다. 스매시도 같은 입력 흐름으로 통일한다.
- 정확한 타이밍은 빠르고 정확한 샷, 이르거나 늦은 유효 타이밍은 느리고 부정확한 샷으로 연결한다. 너무 이르거나 늦으면 헛스윙이다.
- 오래된 랠리/샷 시퀀스, 상승 중 타격, 거리/높이 위반, 중복 입력은 서버 검증한다. 클라이언트의 타격시각/품질을 신뢰하지 않는다.
- 이전 1인칭·분할 구현은 비교용 개발 옵션으로 보존하고 일반 플레이에서는 사용하지 않는다.
- 기존 실행 게임은 임의 종료하지 않는다. 새 패키지와 독립 검사 프로세스로 검증한다.

## 미완료 사항

사용자 실제 조작감 평가 및 Windows + Alt + R 수동 MP4 녹화는 별도 진행이 필요하다.

### 구현 진행 1

- 전체 3인칭 카메라, 로컬 몸체 표시, 목표 지점 마우스 조절, 모든 샷의 좌클릭 타격 흐름을 구현했다.
- 하강 타격면의 시간을 기존 중력/항력 궤적에서 수치적으로 구한다. 기본 허용 오차 ±0.22초, PERFECT 구간 ±0.045초이며 실제 거리/샷별 높이 제한도 적용한다.
- 서버 GameMode에서 품질과 궤적을 재계산한다. 품질이 낮으면 비행 시간이 늘고 목표에 오차를 추가하며, 오차를 코트 안으로 강제 보정하지 않는다.
- 구형 1인칭 타격 RPC는 새 조작 모드에서 차단한다. 서버 시퀀스가 다른 요청은 거절한다.
- 하강/상승·거리·늦은 입력과 타이밍별 실제 궤적 테스트 2개를 추가했다. 컴파일에서 로컬 변수의 Player 멤버 이름 가림을 확인해 PlayerPosition으로 수정했다.

### 검증 진행 2

- 에디터 빌드 성공. 신규 하강 타이밍/궤적 2개 포함 Unreal Automation 28개 통과. 로그: Saved/Logs/Automation-ThirdPerson.log.
- AI 실제 렌더 테스트에서 5종 모두 타격(contact=5, mask=62), 라켓 시선과 무관한 판정, 중복 시퀀스 거절을 확인했다. 로그: BadmintonThirdPerson-20260921-085844.log.
- 초기 화면에서 중앙 하단 안내가 캐릭터를 가리는 것을 확인해 타이밍 안내를 왼쪽 아래로, 판정 메시지를 위로 옮겼다.
- 기존 1인칭 테스트 스크립트에는 비교 전용 -BadmintonLegacyFirstPerson 옵션을 명시했다. 2인 검사에 ThirdPerson 모드를 추가하고 PIE 검사는 현재 기본 플레이 모드를 확인하도록 갱신했다.

### 검증 진행 3

- 실제 PIE 검사 PlayModePIE 통과: 전체 화면, 로컬 몸체 투영, 보조 캡처 비활성, 전환 키 후 상태 유지 및 목표 지점 투영. 로그: BadmintonDualViewPIE-20260921-090246.log.
- 첫 2인 지연 검사 실패(호스트는 서브 가능, 참가자 이벤트 Dispatch=0). LocalPredicted 능력을 원격 소유 폰의 서버에서 이벤트로 시작할 수 없는 GAS 제약을 확인했다.
- 3인칭 전용 ServerInitiated 능력 6개를 도입했다. 서버 타이밍 승인·비용·회복 처리를 유지하면서 소유 클라이언트의 스윙 연출도 실행한다. 기존 1인칭과 AI 능력은 원래 정책을 유지한다.
- 수정 후 에디터 빌드 성공. 네트워크 검사는 재실행 중이며 최초 실패를 성공으로 간주하지 않는다.

### 검증 진행 4

- 수정 후 독립 호스트·참가자 모두 5종 샷 통과(mask=62). 서버에서 양쪽 각 6회(서브 포함) 접촉 성공, 호스트에서 오래된 시퀀스 재전송 중복 방지 확인. 참가자의 duplicateGuard=0은 해당 중복 주입 검사가 호스트에서만 실행됨을 명시한 값이다.
- 조건: 편도 지연 설정 50ms, 송신 손실 설정 1%, RoundTrip 표시 시계. 실제 선택 RTT 중앙값 154.554ms, p95 158.574ms로 설정값과 구분한다. 외삽 상한 초과 1/102 표본. 짧은 5종 타격 검사이며 장시간 경기·EOS·외부망 완료를 뜻하지 않는다.
- 로그: BadmintonHost-20260921-090923-17932.log / BadmintonClient-20260921-090923-17932.log. 같은 날짜의 네트워크 계측 문서에 상세 통계를 저장했다.
- BadmintonThirdPerson 별도 Windows 패키징 시작. Start-BadmintonAI.cmd와 신규 Start-BadmintonThirdPerson.cmd는 새 3인칭 패키지를 실행하도록 연결한다. 기존 이름의 Start-BadmintonDualView.cmd는 이전 분할 화면 패키지를 직접 실행하도록 보존한다.

### 패키지 확인 및 검사 보완

- Windows 패키징 성공: BadmintonPackage-20260921-091004.log, ExitCode=0. 렌더 스크린샷에서 전체 3인칭, 몸체, 네트, 착지 안내, 타이밍 패널을 직접 확인했다.

## 실행과 조작

- `Start-BadmintonThirdPerson.cmd` 또는 `Start-BadmintonAI.cmd`를 실행한다. 새 패키지는 `Saved/Packages/BadmintonThirdPerson/Windows/`에 있다.
- Enter: 준비/재경기. WASD: 이동. Shift: 대시.
- E 클리어, Q 드롭, 2 스매시, R 헤어핀, Space 리시브를 선택한 뒤 좌클릭으로 타격한다. 서브 차례에는 좌클릭이 서브다.
- 마우스: 상대 코트의 AIM 지점 이동. 가운데 클릭: 목표 초기화.
- CONTACT 원 쪽으로 이동하고 셔틀이 내려올 때 왼쪽 아래 타이밍 표시를 보고 누른다. 라켓 방향을 셔틀과 직접 일치시킬 필요가 없다. 거리와 샷별 높이는 유효해야 한다.
- 정확한 타이밍은 빠르고 정확한 비행, 유효하지만 이르거나 늦은 타이밍은 비행 시간 증가와 목표 오차가 적용된다. 중력·항력은 기존 실제 비행 계산과 공유한다. 너무 이르거나 늦으면 타격하지 못하고 스윙 비용과 회복은 남는다.
- 기본 화면은 전체 3인칭이며 V로 1인칭에 들어가지 않는다. 이전 분할 화면 패키지는 `Start-BadmintonDualView.cmd`에 비교용으로 보존했다.

## 제한 및 미완료

- 이번 검증은 로컬 AI와 같은 PC의 독립 프로세스다. 별도 PC/LAN, EOS 인증·외부망, 전체 RTT/손실 조합, 장시간 경기 검사를 이번 변경에서 수행하지 않았다.
- 서버 도착 시점으로 타격을 판정하며 과거 입력 되감기 보상은 추가하지 않았다. 실제 네트워크 지연에 따라 타이밍 체감은 달라질 수 있다.
- 사람의 조작감 평가는 새 실행 화면에서 필요하다. Windows + Alt + R 시작/종료는 사용자 수동 입력 방식이므로 이번 작업의 MP4 시연 영상은 미완료다. PNG와 자동 검사를 녹화 완료로 표시하지 않는다.
- 커밋·PR은 만들지 않았다. 기존 사용자 변경을 유지했다.
