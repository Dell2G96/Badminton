# 남은 작업과 배포 우선순위

- 확인 시각: 2026-09-21 13:41, Asia/Seoul.
- 작업 모델: GPT-6.
- 요청: 현재까지의 구현을 기준으로 앞으로 남은 작업을 정리한다. 이번 요청에서는 기능을 추가하거나 실행 중인 게임을 변경하지 않는다.

## 현재 완료 범위

3인칭 기본 플레이, 낙하 타이밍 기반 타격, 마우스 목표 이동 감도 확대, E/Q/Space 즉시 타격, 기존 스매시 입력, 한국어 UI, 위치에 따른 드롭·헤어핀 자동 선택을 구현했다. 통합 Q는 네트에서 짧은 서비스 라인 198cm까지 헤어핀, 그 뒤는 드롭이며 서버가 타격 시점의 캐릭터 위치로 결정한다.

로컬 1대1과 연습 AI, 이동·대시·스태미나, 서버 셔틀 시뮬레이션, 자체 간소화 11점 경기·재경기, Windows Development 패키지가 있다. 최초 계획에서 AI는 후속 범위였지만 현재 연습용 AI는 구현되어 있다. 1인칭과 분할 화면은 비교용으로 보존하며, 사용자 결정에 따라 앞으로의 우선 대상은 3인칭이다.

최신 드롭 통합 빌드는 에디터 빌드, 핵심 자동화 3개, PIE, AI 및 별도 프로세스 2인 타격 검사, Windows 패키징을 통과했다. 최신 검사 결과는 [드롭과 헤어핀 위치 자동 통합](<26.09.21 - 드롭과 헤어핀 위치 자동 통합 - GPT-6.md>)에 있다. 이전 빌드의 경기 종료·재경기 검사 성공을 최신 빌드 전체 검증으로 간주하지 않는다.

## 우선순위와 완료 기준

| 순서 | 남은 작업 | 완료 기준 |
|---|---|---|
| 1 | 실제 3인칭 조작감 조정 | 사용자가 직접 플레이해 4배 마우스 감도, 타격 허용 시간, 카메라와 셔틀 가독성, Q 전위·후위 전환을 확인하고 불편 사항을 반영한다. 샷·스태미나·AI 난이도도 조정한다. |
| 2 | 최신 빌드 경기 전체 재검증 | 서브부터 11점 종료·재경기까지 반복하고, 스태미나 부족·연속 입력·늦은 타격·네트 상황·참가자 이탈·호스트 종료를 확인한다. 기존 성공 이력이 있으나 최신 입력과 물리 변경 후 회귀 검사가 필요하다. |
| 3 | 온라인 로비 화면 연결 | EOS 로그인·방 생성·검색·참가 기능을 방 목록, 선택, 접속 상태와 오류 안내 화면에 연결한다. 현재 단축키와 기반 코드가 있다. |
| 4 | 실제 EOS 인터넷 대전 검증 | 서로 다른 실제 계정과 PC/외부망에서 로그인, 방 생성·검색·참가, P2P 연결, 경기·재접속·실패 처리를 확인한다. 첫 배포의 필수 조건이다. |
| 5 | 네트워크·성능·연출 보완 | RTT/손실 조합과 호스트·참가자 역할 교환, 다른 PC/LAN, 장시간 플레이를 검증한다. 캐릭터·이동·스윙 애니메이션, 타격 피드백과 효과음도 다듬는다. |
| 6 | 배포 마무리와 시연 기록 | 배포용 빌드와 런처·사용법을 정리하고 깨끗한 PC에서 실행을 확인한다. 변경 파일을 검토·버전 관리하며 Windows + Alt + R 시연 영상을 저장·검증한다. |

온라인 로비 구현과 인터넷 검증은 서로 영향을 주므로 병행할 수 있다. 그래픽 완성도는 별도 단계로 조정할 수 있지만 EOS 인터넷 대전은 초기 배포에서 제외할 수 없다. 현재 질문에 대한 우선순위 제안이며 새 구현·커밋·배포 승인을 의미하지 않는다.

## 확인 근거와 검증의 한계

- 초기 계획 및 AGENTS.md: Windows 1대1, 자체 간소화 11점 경기, EOS 첫 배포 필수, RTT 100ms·손실 1%에서 안정적인 랠리가 목표다.
- 최신 타격 검사는 5종 타격 성공을 확인했다. 최신 빌드의 장시간 전체 경기·재경기와 모든 지연 조합까지 확인한 것은 아니다.
- 최신 지연 검사는 편도 설정 50ms·송신 손실 1%이며 실제 선택 RTT 중앙값은 약 154.940ms다. 이를 실제 RTT 100ms 검증으로 표현하지 않는다. 목표 검사 축은 RTT 0/50/100/150ms와 손실 0/1/3%다.
- 서버 도착 시점 판정의 지연과 진영별 체감 차이를 계측한 뒤 필요하면 제한적인 지연 보상을 설계한다. 과거 시점 되감기 보상을 이미 구현했다고 표시하지 않는다.
- `BadmintonOnlineSubsystem.h`의 `GetStatus()`, `GetRoomLabels()`, `GetConnectionNotice()`는 Source 검색에서 호출부가 없다. `BadmintonPlayerController.cpp`에는 F1~F5 EOS 조작이 연결되어 있으므로 온라인 기반 전체가 없는 것이 아니라 사용자 화면 연결이 남은 상태다.
- EOS 기반 코드와 합성 설정 검사는 완료 기록이 있지만 실제 계정 로그인·외부망 검증은 미완료다. 기존 기록상 도메인 부재로 브랜드 설정이 보류되어 있으며 현재 외부 콘솔 상태를 이번 작업에서 재확인하지 않았다.
- `BadmintonCharacter.cpp`는 기본 원통형 몸체를 사용한다. 기본 스윙과 피드백이 있으므로 연출 전체가 없다고 표현하지 않고 실제 캐릭터·애니메이션 고도화로 구분한다.
- 사람의 조작감 최종 평가와 이번 단계의 수동 MP4 녹화는 미완료다. 녹화는 사용자가 Windows + Alt + R로 시작·종료하고, 결과를 `Docs/_녹화파일/`에 정리해 디코딩 및 화면 내용을 확인해야 한다.

## 후속 확장 범위

복식, 자동 매칭, 랭크, 전용 서버, 관전·리플레이, 성장·장비·꾸미기는 기본 게임과 인터넷 대전이 안정화된 다음 범위다. 별도 확정 일정이나 근거 없는 완료율은 제시하지 않는다.

## 이번 작업 수행 및 검증

- 진행 안내: 현재 작업 기록과 초기 계획을 비교해 완료 기능과 배포 전 작업을 구분한다고 안내했다.
- 진행 확인: 기본 기능과 드롭 통합 완료, 조작감·전체 경기 검증·EOS 및 온라인 화면 연결이 남았다고 안내했다.
- 저장소 상태와 최근 이력, KST 날짜, 기존 구현 문서와 관련 C++ 코드를 읽어 비교했다. 사용자 변경을 되돌리지 않았다.
- 변경 파일: 이 문서만 추가했다. 소스·에셋·설정·실행 중인 게임은 변경하지 않았다.
- 검증: 문서 내용, 날짜·파일명·관련 문서 링크를 확인했다. 문서만 작성했으므로 새 빌드나 테스트는 실행하지 않았다. 위 테스트 성공은 기존 작업 기록에 근거한다.
- 미완료: 표의 개발·검증 항목은 이번 작업에서 수행하지 않았다. 커밋·PR·시연 영상은 생성하지 않았다.

## 최종 사용자 전달

기본 플레이 기능은 구현되어 있으며, 앞으로는 다음 순서가 좋다.

1. 3인칭 조작감 확정: 마우스 감도, 타격 타이밍, 드롭·헤어핀 전환과 AI 난이도 조정.
2. 최신 빌드 전체 경기 검증: 서브 → 랠리 → 11점 종료 → 재경기, 연속 입력·접속 종료까지 검사.
3. 온라인 로비 완성: 방 목록, 방 선택, 접속 상태와 오류 안내 화면 연결.
4. EOS 실제 인터넷 대전: 서로 다른 계정·PC·외부망에서 접속과 경기 검증. 첫 배포 필수 항목.
5. 품질·배포 마무리: 지연·손실 및 성능 검사, 캐릭터·애니메이션·타격 연출 개선, 배포 빌드와 시연 영상 정리.

다음 작업은 3인칭 조작감 테스트와 최신 빌드 전체 경기 검증을 먼저 진행하는 것을 권장한다. 1인칭은 보류하고 복식·랭크·리플레이는 후속 확장으로 둔다.
