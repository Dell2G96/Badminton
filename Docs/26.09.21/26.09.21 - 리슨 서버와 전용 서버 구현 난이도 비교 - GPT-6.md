# 리슨 서버와 전용 서버 구현 난이도 비교

- 작성 시각: 2026-09-21 13:58, Asia/Seoul.
- 작업 모델: GPT-6.
- 요청 요약: 리슨 서버와 데디케이티드 서버 중 어느 쪽이 구현하기 쉬운지 설명한다.

## 결론 및 사용자 전달

현재 프로젝트에서는 **리슨 서버가 더 쉽게 완성할 수 있는 방식**이다. 이미 리슨 서버에서 경기·복제를 구현했고 별도 게임 서버 배포와 운영이 필요하지 않기 때문이다.

| 비교 | 리슨 서버 | 데디케이티드 서버 |
|---|---|---|
| 초기 구현·배포 | 현재 구조를 이어서 완성 | 서버 빌드·실행·접속 경로와 배포 추가 |
| 서버 운영 | 방장 PC가 담당 | 별도 서버 환경 관리·운영 비용 필요 |
| 판정 조건 | 방장이 서버와 같은 프로세스여서 지연상 유리 | 양쪽 모두 서버에 접속해 방장 특혜를 줄임. 각자의 회선 지연 차이는 남음 |
| 방장 종료 | 서버도 종료 | 한 플레이어가 나가도 서버 프로세스는 유지. 경기 처리 정책은 별도로 구현 |

타격·득점·복제 같은 핵심 멀티플레이 로직은 두 방식 모두 필요하다. 데디케이티드 서버가 게임 로직 전체를 더 어렵게 만드는 것은 아니지만, 독립 서버 빌드·운영과 로컬 플레이어가 없는 환경의 검증이 추가된다. 리슨 서버도 EOS 인증·외부망 접속·NAT·호스트 종료 처리는 검증해야 한다.

현재 1대1 시제품 완성과 조작감 테스트를 우선하면 리슨 서버를 유지하는 편이 수월하다. 장기 목표가 공정한 랭크 대전이라면 데디케이티드 서버가 더 적합하다. 기존 서버 권한 판정·복제는 재사용할 기반이지만 전환을 설정 한 줄로 완료할 수 있다고 보장하지 않는다. 현재 코드의 구체적인 전환 공수는 별도 점검 전에는 확정하지 않는다.
