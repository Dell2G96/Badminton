# 좌클릭 타격과 쉬운 퀵 리시브

## 요청과 구현
- 사용자: Space 타격을 좌클릭으로 변경. 퀵 리시브는 타이밍 없이 마우스와 셔틀콕을 맞춰 적당히 넘기기.
- 타격 입력과 HUD 안내를 좌클릭으로 변경.
- 4번 리시브는 타이밍 게이지·시간 만료·타이밍 위력/오차를 제거. 흰 라켓을 셔틀콕에 맞추고 좌클릭하면 일정한 속도의 리턴. 물리적인 거리·높이·코트와 랠리 검증은 유지.
- 드롭/스매시/하이클리어와 서브는 기존 게이지를 좌클릭으로 입력.
- 기존 바로가기의 BadmintonFPS 패키지를 다시 빌드할 예정.
- 변경 파일: BadmintonPlayerController.h/.cpp, BadmintonGameMode.cpp, BadmintonHUD.cpp.
- 변경 전 사본: ClickReceiveWork/Before.

## 진행 및 검증

- 통합 검사에 실제 좌클릭 바인딩 호출, Space 바인딩 제거, 가상의 이른/늦은 시간에서도 퀵 리시브 성공 확인을 추가.

## 에디터 검증 결과
- 최초 빌드: 실행 중인 사용자 UnrealEditor가 기존 DLL을 점유하여 링크 실패(LNK1104). 소스 컴파일은 성공.
- 사용자 에디터를 종료하지 않고 `-ModuleWithSuffix=FPS_Dell2g,1904`로 별도 DLL 빌드 성공. 다음 에디터 실행에 사용되는 모듈 목록이 새 DLL을 가리킴. 현재 열려 있는 에디터 세션은 기존 코드 유지.
- 자동화 16개 성공, 종료 코드 0. `Saved/Logs/Automation-ClickReceive-20260915.log`.
- 렌더러 통합 검증 성공. 실제 등록된 좌클릭 입력 바인딩을 호출하여 서브/드롭/스매시/하이클리어/리시브의 GAS 타격 확인. `Saved/Logs/BadmintonTiming-20260915-190415.log`.
- 퀵 리시브 검사에서 가상 타이밍 기준을 2초 뒤와 2초 전으로 바꿔도 준비 유지·타격 성공. 두 경우 모두 품질 0.65, 비행 1.35초, 동일 착지점. 타이밍 위력/정확도 영향 없음.
- 잘못된 라켓 정렬은 헛스윙, 반복 클릭은 추가 타격 없음. Space 바인딩 없음.
- 실제 렌더러 스크린샷에서 퀵 리시브 게이지 없음, 좌클릭 정렬 안내, 반투명 라켓을 확인.

## 사용 방법과 최종 안내
- 타격: 마우스 좌클릭. Space 타격 바인딩 제거.
- 1 드롭 / 2 스매시 / 3 하이클리어: 번호 선택 후 게이지에 맞춰 좌클릭.
- 4 퀵 리시브: 타이밍 게이지 없이 흰색 라켓을 셔틀콕에 맞추고 좌클릭. 일정한 강도로 넘어가며 실제 타격 거리와 높이 안에 있어야 함.
- 서브는 기존 게이지를 사용하며 좌클릭으로 입력.
- [게임 바로 실행](D:/_Projects/FPS_Dell2g/Start-BadmintonFPS.cmd).
- 이미 켜져 있는 게임은 종료 후 위 바로가기로 새로 시작. 사용자 에디터 세션은 작업 도중 종료하지 않았음.
- 실제 사람이 조작하는 PIE·MP4 시연은 미완료이며, 이번 검증은 독립 게임 프로세스의 렌더러 및 등록된 입력 바인딩/GAS 경로를 사용함.

## 후속 문의: 모든 창 왼쪽 위의 초록색 프레임 숫자
- 사용자 문의: 갑자기 모든 창 왼쪽 상단에 초록색 프레임 표시가 나타나는 이유.
- 실행 프로세스 조회에서 bdcam(PID 13212), bdcam32.bin(PID 21092) 실행 중 확인. NVIDIA Overlay도 실행 중이므로 화면을 직접 보지 않은 상태에서 원인을 확정하지 않음.
- 앞선 시연 녹화 확인 과정에서 실행을 시도한 반디캠의 FPS 오버레이가 남아 있을 가능성이 높음.
- 공식 안내에서 반디캠 게임 녹화 모드의 초록색 FPS 숫자가 왼쪽 위에 나타나며 FPS 표시/숨김 기본 단축키가 F9임을 확인.
- 안내: F9로 숨기거나 반디캠을 종료. 실제 설정 변경이나 프로그램 종료는 수행하지 않음.
