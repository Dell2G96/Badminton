# UI 타이밍과 실제 타격 판정 설명

## 요청 요약
UI 타이밍이 실제 셔틀콕을 치는 타이밍과 동일한지 확인 요청.

## 수행 내용과 검증
BadmintonPlayerController.cpp의 ServerArmTiming, ServerStrikeTiming, GetTimingProgress, GetTimingPerfectPosition 및 실제 접촉 판정 흐름을 확인했다. UI와 타이밍 품질 판정은 동일한 TimingPerfectAt과 서버 시간을 사용한다. 기준 시각은 기술 선택 시 셔틀콕이 자기 진영에서 내려오며 스매시 265cm, 드롭/클리어 235cm 높이에 도달할 것으로 예측한 시각이다. 플레이어의 거리와 이후 이동에 맞추어 지속 갱신하지 않는다.

좌클릭 요청 처리 시 거리, 높이, 조준 방향 등의 접촉 조건을 별도로 검사한다. 라켓의 0.22초 스윙 연출은 클릭 후 재생되며 메시 충돌이나 애니메이션 접촉 프레임이 타격을 발생시키지는 않는다. 퀵 리시브는 타이밍 품질 판정을 사용하지 않는다.

## 변경 파일
이 설명 문서만 작성. 게임 코드 및 에셋 변경 없음.

## 미완료 사항
이번 확인은 코드 검토이며 실행 테스트, 빌드, 영상 녹화는 수행하지 않았다. 실제 도달 가능 거리까지 반영하는 타이밍 예측 개선은 구현하지 않았다.

## 최종 답변
완전히 동일하지는 않습니다. UI의 녹색 구간과 PERFECT 판정은 같은 시간 기준을 사용하지만, 실제 타격 성공은 별도 조건도 만족해야 합니다.

- 게이지: 셔틀콕이 예상 타점 높이에 내려오는 시각을 표시합니다.
- 실제 타격: 좌클릭 순간 거리·높이·조준 방향을 검사합니다. 게이지가 맞아도 멀거나 조준이 어긋나면 헛스윙할 수 있습니다.
- 라켓 모션: 클릭 후 재생되는 연출이어서 눈에 보이는 접촉 순간과 판정이 정확히 일치하지는 않습니다.

퀵 리시브는 타이밍 판정을 사용하지 않습니다.
