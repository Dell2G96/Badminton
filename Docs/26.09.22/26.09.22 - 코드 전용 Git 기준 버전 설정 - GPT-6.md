## 사용자 결정과 범위

1. Git 버전 관리 안내 후 사용자가 “작업 진행”을 요청했다.
2. 원격 백업 주소를 질문했고 사용자가 `https://github.com/Dell2G96/Badminton`을 지정했다.
3. 이후 사용자가 “map ,asset 파일은 올리지 마”라고 범위를 수정했다. 최종 정책은 코드·설정·스크립트·텍스트 문서만 저장하는 것이다.
4. `Content/`와 맵·이미지·모델·오디오·영상·폰트 등 바이너리 에셋은 로컬에 그대로 보존한다. Git에는 업로드하지 않는다.

이전 [Git 버전 관리 안내](<26.09.22 - 현재 프로젝트 Git 버전 관리 안내 - GPT-6.md>)의 에셋 LFS 제안보다 이 문서의 사용자 확정 정책이 우선한다.

## 확인 사항과 이력 구성

- 작업 시작 시 로컬은 `master`, 최신 커밋은 `682ce97`이며 기존 커밋은 2개였다. 다수의 배드민턴 코드와 스크립트가 미추적 상태였다.
- 원격은 `main`의 초기 커밋 `b19d9c7`과 `.gitignore`만 존재했다. 로컬 기존 이력과 공통 조상이 없다.
- 로컬 과거 이력의 `Config/DefaultEngine.ini`에 Android File Server의 비어 있지 않은 `SecurityToken`이 존재했다. 값은 기록하지 않는다. 현재 설정에서는 해당 값을 비웠다.
- 기존 로컬 `master`는 보존하며 원격에 올리지 않는다. 원격 초기 커밋을 부모로 하여 현재 코드 스냅샷을 `main`에 저장한다. 원격 이력을 강제로 덮어쓰지 않는다.
- 이 방식으로 기존 FPS 이력과 제거 전 토큰을 원격으로 전송하지 않고 현재 상태부터 코드 이력을 관리할 수 있다. 과거 로컬 `master`를 원격에 push하거나 `main`에 병합하지 않는다.

## 수행 내용

- `.gitignore`: 문서와 지침의 일괄 제외를 해제했다. `Content/` 전체와 바이너리 에셋 확장자는 제외하며, 비밀 파일·빌드 생성물·녹화·IDE 파일 제외 규칙을 보강했다.
- `AGENTS.md`: 사용자 지정 원격, 코드 전용 관리, 기능별 `codex/` 브랜치, 검증 후 기능 단위 커밋 정책을 기록했다.
- `Config/DefaultEngine.ini`: 기존 Android File Server 토큰을 비웠다. EOS 자격 증명은 제외된 `LocalSecrets/`에 그대로 유지한다.
- 에셋 포함을 준비하면서 생성했던 `.gitattributes`는 사용자 정정 후 삭제했다. 에셋 LFS 등록은 최종 구성에 포함하지 않는다.
- 기존 IDE 파일과 플러그인 아이콘은 새 코드 전용 스냅샷의 추적 대상에서 제외하고 로컬 파일을 유지한다.
- 기존 게임 소스·스크립트·설정 변경은 현재 기준 스냅샷으로 저장한다. 이번 작업에서 게임 로직을 새로 구현했다고 표시하지 않는다.

## 진행 기록

- 현재 프로젝트 기준 커밋 및 제외 파일 확인을 진행하겠다고 안내했다.
- 에셋 약 408MB와 기존 토큰 발견을 알렸다. 이후 사용자 요청으로 에셋 포함 계획을 취소했다.
- 지정된 원격 초기 이력을 보존하며 로컬 과거 토큰 커밋을 업로드하지 않는 방식을 안내했다.
- 맵과 에셋은 업로드하지 않으며 아직 커밋·업로드가 실행되지 않았음을 알리고 코드 전용 설정으로 전환했다.

## 검증 계획과 한계

- 커밋 대상의 경로·확장자를 검사하여 Content·바이너리 에셋·비밀 파일·생성물이 포함되지 않았는지 확인한다.
- 텍스트 파일의 비밀 값 패턴 검사에서 발견된 EOS 스크립트 항목은 합성 설정 검증용 문자열임을 확인했다. 실제 EOS 자격 증명 파일은 읽거나 복호화하지 않았다.
- Git 저장·전송 무결성과 원격 커밋 일치를 확인한다. 텍스트 패턴 검사는 모든 비밀 값 부재를 보증하는 전문 보안 감사가 아니다.
- 이번 작업은 버전 관리 구성 및 현재 상태 보존이다. 에디터 빌드·PIE·자동화 게임 테스트·패키징·녹화는 재실행하지 않으며 코드 기준 스냅샷을 검증된 배포 버전으로 표시하지 않는다.
- Git에서 내려받는 코드만으로는 맵·블루프린트·에셋이 복구되지 않는다. 실행 환경 복원에는 로컬 Content 등의 별도 백업이 필요하다.

## 앞으로의 사용법

```powershell
git switch main
git pull --ff-only
git switch -c codex/작업명
# 코드 수정과 관련 검증을 수행한다.
git status
# 해당 작업의 코드·설정·테스트·문서 경로만 선택하여 git add 한다.
git diff --cached --stat
git diff --cached
git commit -m "변경 내용을 설명하는 한국어 제목"
```

검증된 작업만 `main`에 병합하고 사용자 지시 범위에 따라 원격에 push한다. 아직 커밋하지 않은 변경이 있으면 먼저 별도로 보존한다. 맵·에셋에 `git add -f`를 사용하지 않는다.
