## 진행 기록

- 최근 문서와 현재 코드를 대조하고 바로 진행 가능한 항목부터 처리하겠다고 안내했다.
- 방 목록·선택·접속 상태 화면이 빠진 것을 확인하고 먼저 구현한 뒤 빌드·자동화·PIE·2인 회귀를 수행하겠다고 안내했다.
- 별도 기능 브랜치를 만들었고 기존 main과 맵·에셋을 보존했다.
- 최초 에디터 빌드는 새 PIE 테스트의 UE 5.7 입력 바인딩 API 사용 오류로 실패했다. Binding.Key를 Binding.Chord.Key로 수정했고 두 번째 빌드는 성공했다. 실제 실패를 성공으로 표시하지 않는다.
- 로비 닫기 클릭이 같은 프레임의 게임 타격으로 전파되는 것을 막기 위해 닫은 직후 0.15초간 게임 입력을 차단했다. 1인칭 타이밍 준비 경로에도 같은 차단을 적용한다.
- 첫 전체 자동화는 32개 중 31개 통과, 새 방 선택 테스트 1개 실패였다. 실패 원인은 테스트에서 GameInstanceSubsystem을 올바른 GameInstance 소유자 없이 생성한 것이다. 테스트 소유자를 수정했다. 로비 PIE·카메라 PIE와 기존 3인칭 검사는 첫 실행에서도 통과했다.
- 수정 후 에디터 최종 빌드 성공, 전체 자동화 32개 성공·실패 0, 로비 PIE와 카메라 PIE 통과. 로그: Saved/Logs/Build-OnlineLobby-Final.log, Automation-OnlineLobby-Final.log.
- Windows 패키지 BadmintonOnlineLobby 생성 성공. 로그: Saved/Logs/BadmintonPackage-20260922-064555.log.
- 패키지 화면 캡처 자체는 성공했으나 첫 확인 스크립트가 프로젝트 루트 Saved를 기다려 시간 초과했다. 실제 저장 위치인 패키지 내부 Saved/Screenshots에서 이미지를 확인·복사하고 시각 검토했다. PNG는 로컬에만 보관하며 MP4 녹화 완료로 표시하지 않는다.
- 사용자는 두 번째 PC와 계정이 지금 준비되기 어렵다고 답했다. 실제 EOS 외부망 검증은 이번 실행에서 완료할 수 없으며 별도로 남긴다.
- 에디터 능력 회귀 검사에서 insufficient stamina / free clear 실패가 재현되었다. 구형 1인칭 실행 플래그가 BeginPlay에서 적용되지만 Character의 PossessedBy에서 그보다 먼저 3인칭 능력을 부여할 수 있는 순서 문제를 확인했다. 로비 구현과 별도 논리 변경으로 수정·검증한다.

## 로비 구현 커밋

온라인 방 목록과 접속 상태 화면 연결: 로비 코드·입력 분리·선택 테스트 및 PIE 테스트를 기능 단위로 저장한다. 위 능력 초기화 회귀와 최종 검증 기록은 후속 커밋으로 분리한다.

## 능력 초기화 회귀 수정

- 로비 구현은 16d370e에 저장했다.
- 입력 모드 결정을 PlayerController의 BeginPlay에서 생성자로 옮겼다. Character가 PossessedBy에서 능력을 부여할 때부터 1인칭·3인칭에 맞는 GAS 네트워크 정책을 선택한다.
- 수정 후 에디터 별도 프로세스 능력 검사에서 양쪽 모두 통과했다. 드롭 비용 8, 스매시 18, 대시 25의 한 번 차감, 스태미나 0에서 유료 능력 거절·무료 클리어 허용, 오래된 입력·잘못된 조준 거절, 반복 입력, 대시 이동을 확인했다.
- 로그: BadmintonHost/Client-20260922-065250-21302.log. 대시 이동은 호스트 183.7cm, 참가자 183.9cm였다. 이는 기존 능력 검사 경로의 검증이며 3인칭 전체 키 조합을 모두 검사한 것으로 표현하지 않는다.
- 로비 패키지의 2경기·재경기·22개 고유 랠리 득점, 3번째 참가자 정원 거절, 참가자 재접속, 호스트 종료 후 오프라인 복귀도 모두 통과했다. 로그: BadmintonHost/Client-20260922-064805-21301.log. 이후 초기화 수정의 최종 패키지 재검증은 별도로 기록한다.

## 구현

- F6으로 열고 닫는 한국어 온라인 화면, F1 로그인·F2 방 생성·F3 검색·F4 선택 방 참가·F5 나가기 연결.
- 방 목록은 한 페이지 6개, 클릭·위아래·페이지 키로 선택. 빈 목록·처리 중·로그인 필요·연결 오류 안내와 비활성 버튼 표시.
- 로비가 열려 있을 때 이동·조준·타격·대시를 차단하고 Enter는 참가로 처리한다. 닫으면 입력을 복원하며 경기는 일시정지하지 않는다.
- 실제 EOS 실행 시 오프라인 초기 코트에서 로비를 자동 표시한다. 온라인 코트 이동 후에는 경기 화면으로 돌아간다.
- 연결 실패 안내가 오프라인 AI 생성만으로 사라지던 조건을 수정하여 사용자가 확인할 수 있게 유지한다.
- 방 선택의 범위·진행 중 변경 차단과 실제 PIE 입력·버튼·화면 검사를 추가한다.

## 실행 방법

1. Start-BadmintonThirdPerson.cmd로 최신 연습 빌드를 실행한다. F6으로 온라인 메뉴를 열고 닫을 수 있다.
2. 실제 EOS 연결은 기존 Start-BadmintonEOS.cmd를 사용한다. 저장한 설정을 읽을 수 없다면 그 설정을 저장한 사용자 Windows 환경에서 직접 실행한다. 비밀 값을 채팅으로 전달하지 않는다.
3. F1 로그인 → 브라우저 동의 → 한쪽 F2 방 생성 → 다른 쪽 F3 검색 → 클릭 또는 ↑↓로 방 선택 → F4/Enter 참가.
4. 코트에서 두 플레이어가 Enter로 준비한다. F5는 온라인 방 나가기다. 메뉴가 게임을 일시정지시키지는 않는다.
5. 연결 오류는 메뉴 상태와 알림으로 확인하고 연결 알림 확인 버튼으로 지울 수 있다.

## 남은 작업과 사용자 결정

- 사용자가 두 번째 PC와 계정을 지금 준비하기 어렵다고 답했으므로 실제 EOS 로그인·방 목록·참가·P2P·외부망 2인 경기의 완료 판정은 보류한다. 실제 서비스의 방 목록과 로그인 실패·취소는 추가 실계정 검증이 필요하다.
- 별도 PC/LAN, 역할 교환, 전체 12개 지연·손실 조합, 장시간 경쟁 랠리, 사람의 3인칭 조작감 확정은 남아 있다.
- Windows + Alt + R MP4 시연은 사용자의 시작·종료 협업이 필요하여 이번에는 녹화하지 않았다.
- 맵·에셋의 Git 업로드와 외부 백업은 하지 않는다. 실행 패키지·검사 로그·PNG 역시 로컬에만 보관한다.
- 후속 확장인 복식·전용 서버·랭크·리플레이는 착수하지 않았다.

## 최종 전달 요지

미완료였던 온라인 로비 화면을 구현했고, 확인 과정에서 능력 초기화 순서와 통합 컴파일 오류도 수정했다. 최종 빌드·자동화 32개·PIE·패키지 및 로컬 능력·지연 타격 검사를 통과했다. 실행 메뉴는 새 빌드로 연결했다. 실제 EOS 외부망 검증과 사람의 조작감·수동 영상은 남아 있다. 맵·에셋은 업로드하지 않는다.
